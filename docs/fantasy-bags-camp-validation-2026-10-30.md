## 확인 후 수정한 실제 오류

1. **보존 가방의 일부 수납이 일반 품목 칸까지 비워 주던 문제**: 빵 49개 중 48개만 보존 가방에 들어가면 남은 빵 1개는 일반 가방에서도 한 품목을 차지한다. 기존 계산은 보존 가방에 한 개라도 들어간 종류를 모두 일반 가방의 추가 칸으로 계산했다. `fantasyBagState`의 칸 증가는 전량 수납된 음식 종류에만 적용했다. 음식 12kg/8종 수납 정보와 실제 총 중량은 유지한다.
2. **정리된 던전 방에서 야외 요리를 차단하던 문제**: 요리 전용 검사는 안전한 방을 허용했지만 엔진의 던전 공통 허용 목록에 `campCook`이 빠져 있었다. 공통 목록에 추가하고, 미조사 방은 거부/조사 후 안전한 방은 허용/현재 방 유지까지 공개 액션으로 검증했다.
3. **신선한 보존 음식과 상한 일반 음식을 섞어 새 음식으로 만드는 문제**: 첫 번째 생성 시각의 음식 묶음만 검사하면 보존 덕분에 신선한 오래된 1개와 더 최근에 생성됐지만 상한 1개를 함께 소비할 수 있었다. `fantasyHasSpoiledIngredients`가 실제 FIFO 소비 수량에 들어가는 모든 묶음을 검사한다. 야외 요리와 일반 제작 양쪽에 적용했다. 소비하지 않는 상한 잔여 묶음은 신선한 1인분 요리를 방해하지 않는다.
4. **실제 서버에서 야외 요리가 완료되어도 저장되지 않던 문제**: 야외 요리가 `campCook:...`이라는 대문자 포함 숙련 이력을 만들었지만 저장 검사는 소문자 키만 허용했다. 서버 시계 완료 검사가 `Fantasy clock produced an invalid profile`로 실패함을 확인했다. 숙련 키를 `camp-cook:직업:장소:요리법`으로 기록하도록 수정했다. 공개 요리 결과의 성장 검증과 실제 서버 완료/재시작 검사를 추가했다.
