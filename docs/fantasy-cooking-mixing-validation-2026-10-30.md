## 조합과 조리 판정의 구분

`cookMix` 명령은 `station`, 중복 없는 `ingredients: [{item,count}]`, 필요할 때의 `recipe`, 기존 상업지 주방의 `workshop`만 받는다. 성공 여부, 확률, 보상, 시간, 마법사 권한 같은 클라이언트 제공 값은 허용하지 않는다.

재료 종류·수량이 맞지 않거나, 수량이 부족하거나, 여러 후보를 확정하지 않은 요청은 **원래 상태 그대로 거부**한다. 시간 예약, 재료, 연료, 숙련, 결과물을 변경하지 않는다. 같은 유효 조합을 정수 배수로 만들 수 있으며 한 번에1–10회분, 최대8종, 재료별1–99개로 제한했다. 이 상한은 사용자 지정 값이 아니라 이번 구현에서 정한 보수적인 한도다. 각 회분의 기존 소요 시간을 합산한다.

유효한 조리만 저장된 활동의 난수 시드에서 **d20 한 번**으로 판정한다. 조합 자체에는 실패 확률이 없다. 성공·실패 모두 선택한 재료와 조리 시간을 소비하고, 야외의 목재 방식은 조리 시도당 목재1개를 소비한다. 도구는 남는다. 실패하면 음식이 생기지 않으며 요리 숙련은 성공보다 적게 오른다. 성공하면 정해진 수량의 음식을 **실제 완료 시각의 새 음식 묶음**으로 만든다.

재료 상태는 실제 FIFO 소비에 포함되는 모든 음식 묶음을 사용한다. 보존된 오래된 묶음만 보고 다른 상한 묶음을 놓치지 않는다. 소비할 상한 음식은 거부하며, 사용하지 않는 상한 잔여량은 신선한 재료의 조리를 막지 않는다. 예약 동안 상태가 변하면 완료 때 다시 검사한다. 화면의 확률은 표시된 현재 재료 상태 기준이며 조리 중 노화가 진행될 수 있다.

## 선택한 수치

```text
숙련 보너스 = min(10, floor(sqrt(jobXp.cook) / 3))
재료 상태 부담 = ceil(소비하는 오래된 음식 수량 / 소비 음식 수량 × 3), 음식이 없으면0
묶음 부담 = min(3, floor((회분 - 1) / 3))
필요 눈 = clamp(요리 난이도 - 숙련 보너스 + 재료 상태 부담 + 묶음 부담, 2, 20)
성공 = d20 눈 >= 필요 눈
성공 확률 = (21 - 필요 눈) / 20
```

따라서1은 항상 실패하고20은 항상 성공한다. 확률은5–95% 안에 있다. 같은 재료/난이도에서 요리 숙련이 높아질수록 성공 확률은 내려가지 않으며, 소비하는 오래된 재료 비율이나 난이도가 높아지면 올라가지 않는다. 다른 직업의 전투 능력치나 레벨로 조리 판정을 우회하지 않는다.
