# ログインとゲスト

入口で「Misskey でログイン」か「ゲストで入る」を選ぶ。本人はサーバーが Cookie のセッションで決め、画面から名乗った名前や ID は信じない。部品はサーバーが `server/auth.ts`、画面が `client/src/auth.ts` と `client/src/App.tsx` の入口。

## できること

| | ログインした人（Misskey） | ゲスト |
|---|---|---|
| セッションに入る・話す・セッション内チャット・アイテム | できる | できる |
| アイコン・3D アバターの保存 | できる | できる（その端末のゲストに残る） |
| 自己紹介 | できる | できない |
| チャット・メッセージへの画像の添付と画像アイテム | できる（1 時間に 30 枚・100MB まで） | できない |
| タイムラインへの投稿・リアクション・リポスト | できる | 見るだけ |
| フォロー・DM・グループ・セッション/イベントの作成・参加表明・ステータス・いいね | できる | できない |
| ゲームの進み具合（サバイバーズ） | 残る | 残らない（遊ぶことはできる） |

- ゲストがログインした人だけの操作をすると、サーバーは受け付けずに `loginRequired` を返し、画面に「ゲストは使えません。Misskey でログインすると使えます」と出る（`server/index.ts` の `LOGIN_ONLY`）。HTTP の自己紹介・タイムラインの写真・グループ画像の書き込みもゲストは断る
- ゲストは名前の横に「ゲスト」の印が付く（左のプレイヤー一覧とプロフィールカード）。同じ表示名でもアカウントが違えば別人として扱う。ログインした人のプロフィールカードには Misskey の @ユーザー名を出す
- 表示名は最初は Misskey の名前（ゲストは入口で入れた名前）。設定（プロフィール）の「アカウント」で変えられ、つないでいる全員にすぐ届く。同じ欄にログアウトと、ゲストなら「Misskey でログイン」がある
- 人に結び付くもの（フォロー・DM・グループ・イベント・作ったセッション・タイムライン・ステータス・アイコン・アバター・自己紹介、手元のブロック・個別音量）はすべてアカウント ID で持つ。名前を変えても、それらはそのまま残る（[storage.md](storage.md)）

## Misskey でのログイン（OAuth 2.0）

ログインできる Misskey は 1 つだけ（既定は misskey.resonite.love、`MISSKEY_URL` で変更）。Misskey の OAuth 2.0（認可コード＋PKCE `S256`）を使う。権限は `read:account`（自分のアカウント情報の読み取り）だけを求め、本人確認に使ったトークンはすぐ捨てる。Misskey 側での登録は要らない。アプリのトップページ（`https://<アプリのドメイン>/`）を `client_id` にし、Misskey がこのページを読みに来て、`<link rel="redirect_uri">` の戻り先と `h-app`（名前・アイコン）を確かめる（`client/index.html`）。そのため、本物の Misskey でログインできるのは、アプリのドメインが Misskey のサーバーから HTTPS で読めるとき（本番や公開した検証環境）だけ。手元では開発用ログインを使う。

以前の MiAuth は、許可の結果がセッション ID だけで取れた（`/api/miauth/<セッション>/check`）。始めた人もセッション ID を知っているので、他人に許可 URL を送り、許可された瞬間に先回りすれば入れてしまう。OAuth では、許可の結果（認可コード）は許可したブラウザへのリダイレクトにしか載らず、トークンに替えるには始めたときの PKCE の `code_verifier`（サーバーだけが持つ）も要るので、横から取れない。

1. 画面が `POST /auth/misskey/start` を呼ぶ。サーバーは state（`login_pending` の `session`）と PKCE の `code_verifier` を作って残す。始めた端末にだけ、「待ち合わせ用の秘密」を Cookie（`tonarium_login`、10 分）で、8 文字の「確認コード」（例: `K7QF-2MXP`）を応答で渡し、Misskey の許可画面（`/oauth/authorize`）の URL を返す
2. ブラウザはそのまま Misskey へ移る。許可すると Misskey が `/auth/misskey/callback?code=...&state=...` へ戻す。サーバーは認可コードを `code_verifier` と一緒にトークンに替え（`/oauth/token`）、`/api/i` で許可した人（Misskey のユーザー ID・ユーザー名・名前）を確かめる。待ち合わせの Cookie を持つブラウザ（＝ログインを始めたブラウザ）なら、そのアカウントに結び付け、ログインの Cookie を付けて `/` へ戻す
   - 1 つの state の callback を受けるのは一度だけ（最初に戻ってきたブラウザ。`login_pending.callback_hash`）。拒否された・認可コードが無い・トークンに替えられない・`iss` が違うときは、そのログインを取り消す
3. 待ち合わせの Cookie が無いブラウザ（Electron から始めた、または他人から送られた URL を開いた）には、「〇〇 @ユーザー名 として Tonarium にログインします」と確認コードの入力欄、「自分で始めたときに表示されたコード以外は入れない」という注意を出す。このとき、そのブラウザにだけ HttpOnly の Cookie（`tonarium_confirm`）を付ける。コードは、その Cookie を持つブラウザから送られて合ったときだけアカウントに結び付け（`POST /auth/misskey/confirm`。同じオリジンのフォームだけ受ける）、「アプリに戻ってください」と出す。5 回間違えるとそのログインは取り消す。他人が始めたログインの許可 URL を開かされても、許可しただけでは他人がそのアカウントで入れない（ログイン CSRF の対策）。始めた側はコードを知っていても、この Cookie が無いので確定できない
4. Electron 版は別のサイトへ移らず、許可画面を外のブラウザで開く（`window.open` → 外部ブラウザ）。アプリ側は確認コードを大きく出し、`POST /auth/misskey/poll` を 2 秒ごとに呼ぶ。手順 3 でコードが入って結び付いたら、その場でログインの Cookie を受け取る
5. 同じ Misskey の人は何度ログインしても同じアカウント（Misskey のユーザー ID で引く）。Misskey 側でユーザー名を変えていれば更新する

## セッション

- ログインの Cookie は `tonarium_session`（HttpOnly・SameSite=Lax、HTTPS なら Secure）。中身は乱数で、DB（`auth_sessions`）にはハッシュだけを残す。期限は DB で決め、ログイン 90 日・ゲスト 1 年で、残りが 30 日を切ると使ったときに延ばす（Cookie 自体はブラウザの上限の 400 日まで持たせる）。期限切れは 1 時間ごとに消す
- ゲストで入り直すと、同じ端末（Cookie）のゲストなら同じアカウントのまま名前だけ変わる。ログアウトするとその端末のゲストには戻れない。ゲストを作れるのは 1 つの接続元から 10 分に 20 人まで（超えると 429）。接続元は、信頼するプロキシ（`FANTASY_TRUSTED_PROXY_IPS`・`FANTASY_TRUST_PROXY`。[deploy.md](deploy.md)）からの接続のときだけ、そのプロキシが `X-Forwarded-For` の末尾に足したアドレスを使う（先頭は送り手が選べるため）。信頼するプロキシを設定しないと、前段を通る全員が 1 つの接続元として数えられる
- `/auth/*` の POST は同じオリジンからの fetch だけ受ける（Origin を見る）。他サイトからログインさせたり、名前を変えさせたりできない
- WebSocket（`/ws`）はつなぐ時点でセッションから本人を決める。`hello` は互換性の版だけを送り、セッションが無ければそこで断る（版が古い画面には先に `incompatible` を返して再読み込みを促す）。ログインの導入で `COMPAT_VERSION` を 7 に上げた。ほかのタブでログアウトした・期限が切れたなどで 4401 で断られた画面は、再接続せずに読み込み直して入口に戻る
- HTTP の書き込み（アイコン・アバター・自己紹介・写真・グループ画像・メディア・通報）と翻訳・OGP・LiveKit のトークンは、セッションの本人で受ける。URL の `?id=` は読むとき（だれのアイコンか）にだけ使う

## 開発とテスト

- 環境変数 `AUTH_DEV_LOGIN=1` があり、かつ `NODE_ENV` が `production` でないときだけ、名前だけでログイン扱いのアカウントを作る `POST /auth/dev` が開く（`--dev` だけでは開かない）。本番のイメージは `NODE_ENV=production` なので、書き間違えても開かない（起動時に警告を出す）。手元は `.env` に書く（`.env.example` に入っている）。サーバーを立てるテストは `server/test-db.ts` が付ける
- 開発中は URL に `?as=b` を付けると、その名前の開発用アカウントでそのタブだけ入る。同じブラウザの Cookie は全タブで共有されるので、`?as=` のタブはセッションを `sessionStorage` に持ち、fetch は `X-Tonarium-Session` ヘッダー、WebSocket は `?session=` で送る（開発用ログインが開いているときだけサーバーが読む）
- サーバーのテストは `server/test-auth.ts` の `devLogin(base, 名前)` で入り、返った Cookie を WebSocket と fetch に付ける。ログインそのものは `server/auth.integration.test.ts` が偽の Misskey を立てて確かめる（`npm run test:integration`）
