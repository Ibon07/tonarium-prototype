# 開発の方向性

依頼を受けて何を作るか決めるときの拠り所。人の開発者と Tonarium Agent の両方が読む。細かい禁止事項はここに書かない（Agent 側の判断基準は tonarium-agent リポジトリで管理する）。叩き台のため、方針が変わったらこのファイルを直接直す。

## 目的

2D（リスト・ウィンドウ・チャット・通話・配信視聴）と 3D（空間）を同じワールドのまま行き来できるソーシャル体験を検証する。ここで確かめたいのは「離れた人と同じ場所にいる感じ」が、画面の形を変えても続くかどうか。プロトタイプなので、検証の速さを作りの丁寧さより優先する。ただし、他の機能を壊す近道は取らない。

## 大事にする体験

- **一緒にいる感じ**：距離で変わる声、顔、アイテム、ついていく、のように、同じ場所にいることが伝わる仕組みを優先する。一人で完結する機能より、人と一緒に使える機能を選ぶ
- **2D と 3D の一貫性**：同じアイテム・同じ人・同じ状態が、どちらの表示でも同じ意味を持つ。片方だけの機能を足すときは、もう片方でどう見えるかを決める
- **気軽さ**：入ってすぐ話せる、置いてすぐ遊べる。設定や手順を増やす変更には、それに見合う理由が要る
- **言語の違う人とも過ごせる**：表示は日本語・英語・韓国語。利用者に見える文言は三言語をそろえる
- **既存の仕組みを広げる**：アイテム・ワールド・共有システム・同期など、すでにある仕組みの上に作る。同じ問題に別の仕組みをもう一つ作らない

## 依頼の受け止め方

- 依頼文の条件そのものより、依頼者が困っている場面と、そこで実現したいことを優先する。条件を満たすだけの特別扱いやハードコードで済ませない
- より目的に合う作り方があるなら、実装の前に提案する。既存機能で解決できるなら使い方を案内する
- 一人の要望のための変更が、ほかの利用者の体験を悪くする場合は、そのまま実装しない

## 当面の範囲

- 対象は Web 版（デスクトップの Chrome / Edge 推奨、スマホは 2D の最低限）、Electron 版、単体ブラウザの WebXR
- ネイティブ版（Avalonia／Unity）は廃止済み。復活させない
