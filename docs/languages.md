# 表示言語

Web UI は日本語・英語・韓国語に対応する。参加画面の言語選択、またはプロフィール設定の「表示言語」で変更できる。ホーム左下の歯車、セッションの設定の「プロフィールを編集」からも開ける。切り替えると、開いている画面や通知を更新し、入力中の名前・自己紹介・本文は保持する。

初期表示は次の順で決める。

1. `localStorage` の `tonarium.language` に対応言語の保存値があれば優先する。
2. 保存値がない、非対応、または読み取れない場合は、`navigator.languages` を優先順に照合する。空なら `navigator.language` を使う。
3. 一致しなければ日本語にする。

言語コードは大文字小文字を区別せず、`en-US`、`ko-KR`、`ja-JP` などを基本言語に対応付ける。選択すると基本言語コードを端末に保存する。保存できない場合も、その画面では選択した言語を使う。チャットの翻訳時には、本文と翻訳先の言語コードをサーバーへ送る。

翻訳は `client/src/i18n/ja.ts`、`en.ts`、`ko.ts` の同じキーで管理する。React 以外の描画でも使える処理は `core.ts`、React の購読は `index.ts`、初期判定は `locale.ts` に分ける。組み込みのワールド・アイテム・状態などの共有定義は `static.ts` で表示用に包み、元の共有データを変更しない。固定文言を追加するときは全言語のリソースを追加する。`sourceText` は、既存の文字列型のエラー状態や表示定義に渡す日本語の原文をリソースから取得するために使う。表示時に選択言語へ変換する。

ワールド選択モーダル、移動方法の設定と3D操作案内、バイク乗車中の案内、AD研究所のウィンドウ見出しも同じリソースで翻訳する。移動方法の保存値やキー操作は言語を切り替えても変わらない。

ユーザー名、セッションやグループの名前、自己紹介、付箋本文、作者が登録したマーケットの名前・説明などは翻訳しない。`t` の差し込み引数も原文を保つ。チャット本文は[自動翻訳](chat-translation.md)の対象で、原文を保持したまま表示用の訳文を取得する。`systemText` はサーバーのシステムイベントやエラー、組み込みの表示定義に限定して使い、ユーザーの本文には適用しない。保存後も切り替える通知は `msg` でキーと引数を保持する。

固定UI文言の切り替えに外部APIは使わない。チャットの自動翻訳はサーバーのOpenAI連携で行い、ローカル開発では実APIに接続しないモックを使う。

Service Worker の接続不可・メンテナンス案内も同じ優先順で言語を選ぶ。アプリを読み込めない場合に備え、この案内の翻訳だけは `client/public/offline-locales.js` に置き、生成した案内ページ内に埋め込む。

## 確認

`npm run test:i18n` で言語の優先順、地域付きコード、非対応言語のフォールバック、保存・保存失敗、通知の再翻訳、原文保持、翻訳キーと差し込み引数の一致を検証する。`npm run test:client` にも含める。

画面の確認では、各言語で参加画面、ホームの各ページ、プロフィール、セッションの設定・通知・ログ・アイテム、マーケットを開く。入力途中の名前や本文を残して言語を変え、原文とカーソル操作が保たれることを確認する。Canvas のチェス・キャンバス、3D の案内も確認する。ブラウザの言語を変えて再読み込みし、保存値が優先されること、保存値を削除するとブラウザの優先順に戻ることを確認する。
