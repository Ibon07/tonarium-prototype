# アイテムとメディア共有

アイテムの定義は `shared/items.ts`（状態・操作・リストに出すマークと色）、2D 画面はキャンバスで描くものが `client/src/items/panels.ts`、React で作るウィンドウが `client/src/world/`（サイコロは `DiceBody.tsx`）、3D 表示は `client/src/view3d/items3d.tsx`。

## コードで作るマップへの配置

共有システムのコードマップでは、`createSystemMap(...).item({ id: 'table-one', itemId: 'chess', position: [2, 0, -2] })` で対応する基本アイテムを配置できる。`itemId` は基本アイテムの種類 ID、`id` はマップ内の配置 ID。`chessAi`・`jumpPad` の大文字小文字もそのまま使う。マーケットの商品 ID と画像・YouTube はこの ID 配置には含めない。通常のマーケットや所持アイテムメニューでの購入・利用は従来どおり。

共有システム画面の基本アイテムID一覧とID検索は、通常のアイテムと同じ `shared/items.ts` の `ITEM_INFO` 定義から生成する。新しい基本アイテムを通常の手順で実装し、その定義を追加してビルド・デプロイすると自動で反映される。共有システム専用のID一覧へ重複登録する必要はない。`media: true` のアイテムと、`MARKET_PRODUCTS` で商品IDまたは種類が一致するアイテムは引き続き除外する。

既定の `itemMode: 'native'` は、ゲーム・編集など既存の基本アイテムの機能を保つ。共有システムの接続対象にはしない。`itemMode: 'system'` と必要な `capabilities` を指定すると、そのモデルをボタン・タイマー・着席などのシステムから使う。このモードでは元のゲーム・編集・運搬・削除操作は無効になり、接続したシステムが制御する。文字表示の `text` 機能は付箋（`note`）だけに使える。

配置は床面のみで `position[1]` は `0`。同じマップ・配置 ID では既存状態を再利用する。マップを切り替えたときに片付けるのは、そのマップが作ったアイテムだけで、通常メニューから出した物は保持する。設定例・位置と状態の保持・利用可能な ID は [共有システムのアイテム配置](shared-systems/contracts.md#아이템-메뉴의-아이템을-id로-배치) を参照。

開発用の[ID別カタログ](shared-systems/README.md)と[add-worldの接続手順](../.claude/skills/add-world/SKILL.md)を参照してください。新しい基本アイテムを登録したら `npm run docs:shared-systems` で個別文書を生成し、同じPRに含めます。既存モデルに別の操作を組み合わせたメニュー項目は `shared/item-variants.ts` に登録します。`camera-timer` はその例で、通常の `camera` モデルと別のメニューIDを持ち、出した時点でカメラごとに共有タイマーへ接続します。独自の動作を足す場合は登録情報だけでなく、サーバーとクライアントの接続処理も実装します。

## 画像アイテム一覧

画像アイテムの行では、「絵」のアイコン枠にそのアイテムの `url` のサムネイルを表示する。近距離は32px、中距離は22px、遠距離は20pxで、画像全体の縦横比と既存の行高を保つ。サムネイルへのホバーで同じURLの拡大プレビューを表示する。プレビューは最大640×640pxかつ画面の内側に収め、bodyへのポータルで一覧のスクロール領域による切れを防ぐ。スクロール、マウス離脱、Escapeで閉じる。読み込みに失敗した場合は「絵」のアイコンへ戻し、行の選択・「開く」・メニューは引き続き使える。チャット・画像ウィンドウ・3D表示や、画像以外のアイコンは変更しない。

一覧の表示名は、画像アイテムを出した人の `createdBy` に対応する表示名を使って「○○の画像」とする。更新者 `updatedBy` や現在の所持者は使わない。オンラインの作成者名を優先し、取得できない場合はサーバーが作成時に保存した任意項目 `createdByName` を使う。どちらも欠落または空白なら「画像」と表示する。名前を持たない旧データもそのまま読み込める。追加の名前は画像アイテム全体とともに保存・初期同期・更新同期され、位置だけの同期でも保持される。行とサムネイルはアイテムIDとURLに対応させ、並べ替えで別の画像や名前を流用しない。

確認用コマンドは `npm run test:image-list`。複数投稿者・複数画像の並べ替え、更新者との区別、保存復元、名前欠落・空白、旧データ、画像以外の名前処理と、画面内のプレビュー配置に使う位置計算を対象とする。今回の実行環境ではVoltaの権限エラーでnpmが起動せず、このテストと `npm run check:completion` は未実施。コード上で生成・保存・初期同期・更新・位置同期の保持経路を確認した。実画面での近距離・中距離・遠距離、縦長・横長画像、ホバーとスクロール、読込失敗後の「開く」、画像以外の表示・操作、複数クライアント間の同期と再起動後の復元は未確認。

## 同期と保存

- 移動の同期は位置だけの軽量メッセージ（`itemMove`）で、中身は含めない。作成・内容の更新・削除はアイテム全体を配る（同期の詳細は `docs/sync.md`）
- アイテムは DB の `session_items` に保存され、再起動しても戻る。保存は 5 秒ごとの確認で、アイテムが変わったセッションの分だけ書き直す
- 付箋（2D/3D）: 2D ではウィンドウ、3D では空間内の看板。編集中は他の人に「編集中」と出る
- ピコピコハンマー（2D/3D）: 1本につき1人が持てる。3D では照準で拾い、アバターや 2D の人を叩く。2D では「手に持つ」→ マウスのところにハンマーが出て、リストや顔の人をクリックで叩き、相手のすぐそばに移る
  - 打撃ログは叩く人と相手の識別IDごとに集約し、「X回叩きました」と表示する。直前の打撃から10秒以内（10秒ちょうどを含む）なら同じログの回数と最終打撃時刻を更新する。最初の打撃から10秒を超えても、各打撃の間隔が10秒以内なら集約を続ける。10秒を超えた場合は回数1の新しいログを作る。
- チェス（2D/3D）: クリックで駒を選び、もう一度クリックで移動。ルールは下の「チェス」
- サイコロ（2D/3D）: TRPG 用。ウィンドウで種類（d4・d6・d8・d10・d12・d20・d100）と個数（1〜10）を選んで振る。結果はサーバーが決め、全員が同じ転がり方を見る（3D は木の器の中を転がり、2D はくるくる回る）。転がり終わるとチャットに記録される。「シークレット」で振ると結果は本人にだけ見え、ほかの人には振ったことだけが伝わる。3D では器をクリックすると、最後にウィンドウで選んだ設定で振る
- キャンバス（2D/3D）: みんなで絵を描ける。ペン（6色・細/太）、消しゴム、全部消す、保存（ログに画像で投稿）
- お絵描き伝言（2D/3D）: アイテムのウィンドウで参加登録し、人間2〜30人で文章と絵を交互につなぐ。3D では看板をクリックしてウィンドウを開く。詳しくは下記。
- カメラ（3D 専用）: 持っている間はファインダー表示でクリック = 撮影、L = ライブ配信、Q = 三脚に置く。三脚のカメラは照準で C = 撮影、L = 配信。写真はログに投稿される。ライブは 2D ではウィンドウ、3D ではカメラの上のモニターに映る
  - GIF録画: Escでマウス操作に戻り、右下の「GIF録画」で開始する。手持ちカメラを優先し、手に持っていない場合は三脚カメラを選べる。「録画停止」または開始から10秒で一度だけ終了し、編集プレビューに移る。音声は録音しない。
  - 開始・終了のスライダーをドラッグ、または矢印キーで動かしてフレーム境界を選ぶ。最低1フレームを保ち、端や交差の操作では録画範囲内へ制限する。「再生」は開始フレームから選択区間をループし、「停止」で表示中のフレームを保つ。再び「再生」すると開始フレームへ戻る。
  - 「投稿」で、その時点の区間をGIFに変換し、静止画と同じく現在参加中のセッションの全体チャットへ送る。送信確認まで編集・再投稿を止め、失敗時は録画と選択区間を保持する。再試行は同じリクエストIDを使い、サーバーのチャット履歴に残っている投稿の重複を防ぐ。「閉じる」は録画を破棄する。ページ更新や3D画面の終了をまたぐ編集内容の保存は行わない。
  - 既存の画像投稿上限（data URLで2,000,000文字未満）とGIF表示上限に収めるため、160×90、64色、毎秒最大10フレーム、最大100フレームで収録する。プレビューとGIFは同じ画素・フレーム時刻を使う。時間はGIFの10ms単位へ切り下げ、極端に短い録画は20msまで収録して最低1フレームを確保する。負荷で描画が遅れた場合は最後の取得フレームを次の取得時刻まで表示し、未取得フレームを補間しない。
  - 自動テストは `npm run test:camera-recording`（停止競合・短時間・端/交差・ループ・GIF復号後の画素と区間長・サイズ上限・生成/送信失敗と再試行）、`npm run test:sync`（GIFを含むP2P提案）、`KOKOSYNC_INTEGRATION=1 npm run test:sync:integration`（実接続でのGIF保持と重複抑止）。回帰は `npm run test:camera`、`npm run test:gif`、`npm run test:camera-timer`。
  - 実画面では、手動停止・10秒自動停止・10秒直前からの停止連打・即時停止を試す。両ハンドルの端・交差・1フレーム選択、再生→停止→再生、投稿連打、オフラインでの投稿失敗→再接続→再試行を確認する。フレームごとに変わる被写体を録り、投稿先チャットでGIFが動き、先頭/末尾フレームと区間長がプレビューに合うことを見る。最後にクリック/Cの静止画、Lの配信、通常のJPEG/PNG投稿と既存GIF表示を確認する。自動テストの通過は実画面の受け入れ確認を代替しない。
  - **5秒タイマーカメラ**は別の所持アイテムです。アイテムメニューから出し、クリックまたはCで5秒後の撮影を開始します。残り秒をカメラ上に表示し、開始したタブで秒ごとに効果音を鳴らします。右クリックで移動・回転、Xまたはメニューで片付けます。削除や退出は撮影待ちを取り消します。複数台の状態は独立し、メニューから出したものはコードマップの切替でも残ります。[共有タイマーの接続](shared-systems/camera-timer-test.md)を参照してください。
  - Qを押す直前の手持ちカメラモデルのワールド座標Yを保って設置する。水平位置と向きは従来どおり本人の前方・視線方向から決める。設置先の足元の接地面から脚と支柱を伸ばし、俯角に合わせてカメラ下面を支える。設置後の写真と配信はカメラモデルのワールド位置・向きを共用する。高さ情報のない既存カメラは従来の1.5mで表示する。
  - 高さの回帰テストは `npm run test:camera`。通常操作ではしゃがみ・立位・飛行で低・中・高の高さを作り、各高さでQ設置→クリックで拾う→別の高さでQ再設置→C撮影→L配信の順に確認する。設置前は `Player.tsx` の `cameraRef.current.getWorldPosition(...)`、設置後は `cameraModels` 内のモデルの `getWorldPosition(...)` と `cameraPose(item).pos` をデバッガーで観測し、Y差が浮動小数点誤差の範囲内であることを確認する。脚の接地とカメラ下面までの支持、写真・配信内の高さも目視する。俯角を上下に変えた場合と高い床でも繰り返す。
- 2048（2D 専用）: 全員で1つの盤面を操作。いちばん前のウィンドウなら矢印キーでも動かせる。3D では互換モードとして 2D 画面がパネルで置かれる
- AD ポータル（2D/3D）: どのワールドにも置ける、自分の反物質次元を開く入口。2D では近くのリストやマップから、3D ではミニチュア研究所に照準を合わせてクリックして開く。3D では右クリックで持ち運び、X で片付けられる。進行は自分のプロフィールごとに保存され、複数のポータルから同じ進行を開ける
- バイク（3D 専用）: マーケットで購入し、所有アイテムから出す。一人乗り。操作とモデルは下記。
- 鏡（3D 専用）: 自分と周囲の参加者のアバターや景色を反射する。所有アイテムから配置し、右クリックで運び、Xで片付ける。仕組みと確認手順は下記。
- ジャンプ台（3D 専用）: 所有アイテムから配置する。歩行モードで上面に着地すると、ジャンプ操作なしで自動で跳ね上がる。右クリックで運び、Xで片付ける。仕組みは下記。

## 鏡

所有アイテムの「鏡」から、3D 空間の目の前に配置する。幅1.8m・高さ2.2mの鏡面は正面（ローカル +Z）だけが反射し、裏面は枠と同じ色。照準を合わせて右クリックで運び、視線の向きで鏡の向きを変え、右クリックで置く。Xで片付ける。位置と向きは既存のアイテム同期・保存に従う。2Dからは作成できない。

Three.js の `Reflector` で、描画するカメラを鏡面に対して反転し、鏡面の裏側をクリッピングする。描画のたびに現在のシーンを反射するため、視点・鏡の位置と向き・参加者の移動に追従する。一人称で非表示の自分のアバターも、反射の描画中だけ表示する。一人称の手持ちモデルは隠し、アバター側の装備を映す。通常のWebGL描画に含まれる参加者と景色が対象で、HTMLを重ねるYouTubeプレーヤーなどは映らない。鏡同士の再帰反射は行わない。鏡面ごとに1024×1024の描画を追加するため、多数配置すると描画負荷が増える。そのため鏡アイテムの同時設置は1セッション4枚まで（サーバーが作成時に数え、上限では新しい鏡を作らない。ワールド常設の鏡は数えない）。

反射処理の回帰テストは `npm run test:mirror`。複数人での受け入れ確認は、同じセッションに別々のプロフィールで参加し、両者を3Dに切り替えて行う。

1. 「鏡」を配置し、正面から一人称の自分・相手のアバター・背後の景色が映ることを確認する。
2. 左右・前後に視点を移動し、鏡面との位置関係に応じて映る範囲や角度が変わることを確認する。
3. 双方が歩行・回転・ジャンプし、相手側でも鏡像の動きが更新されることを確認する。
4. 鏡を運んで回転・再配置し、新しい鏡面の位置で反射すること、裏面では反射しないことを確認する。
5. 一人称の通常画面では自分の体が隠れたままで、三人称への切り替え後も反射が続くことを確認する。

この変更では複数人のブラウザ実機確認は未実施。

## ジャンプ台

所有アイテム一覧から「ジャンプ台」を選び、3D空間の床に配置する。半径0.8m、高さ0.18mの台で、右クリックで運び、Xで片付ける。歩行モードで上面に着地すると、ジャンプ操作なしで通常ジャンプと同じ上向き速度4.2m/sを与える。重力は既存の12m/s²を使う。側面に歩いて接触しただけでは発動しないため、通常ジャンプなどで上面へ降りる。

下降中に足元が上面を横切ったときだけ発動する。発動後は上昇状態になるため同じ着地で重複せず、台の上に戻ると再び跳ねる。側面・下面、フライ・ノークリップ、バイク乗車中は発動しない。台は床配置のみで、運んでいる本人には運搬中の台の当たり判定を適用しない。

跳躍回数を既存のアバター同期へ送り、着地まで足元の高さも共有する。他参加者は既存の高さ補間で上下動を表示する。回帰確認は `npm run test:movement` と `npm run test:sync`。複数人の実画面での表示は未確認。実画面では同じセッションの2人を3Dにし、配置、上面着地、側面接触、連続した再着地と、相手側の上下動を確認する。

## AD ポータルと研究所パネル

次元を買って反物質を増やす個人用のゲーム。ポータルを片付けたり、ワールドを切り替えたり、セッションを退出したりしても進行は残る。[AD 研究所ワールド](3d.md#ad-研究所) では同じ進行が空間内の装置に反映される。

- 「次元」で第 1 次元から購入する。「1個買う」「10個まで買う」と Tickspeed、Max All を使える。次元カードには所持量・購入数・生産量・倍率・コストと、動くリアクターが出る
- 「Boost / 銀河 / Sacrifice / Crunch」で条件とリセット内容を確認して進める。Big Crunch までが操作対象で、以降のレイヤーは説明・モック表示。「統計・実績・ランキング」から進行を確認し、スコアを送れる（ランキングには Tonarium の表示名で載る）
- 内容が縦に収まらないときは研究所パネルの中をスクロールする。狭いウィンドウでは購入ボタンが次の行に並ぶ。ボタンのホバー・キーボードフォーカス・無効状態の見た目は、このパネル内に適用される
- 操作成功時に、購入した次元やコアのイラストの周りで小さな粒子が広がり、操作音が鳴る。音量はドックの音量メニューの「サウンドボード・効果音」で調整できる。OS のアニメーション軽減設定に従い、リアクターの回転と購入時の粒子を止める
- 「プロフィール・セーブ」でプロフィールの作成・切替・削除、サーバー保存・読込、最初からのリセット、v2 JSON のエクスポート・インポートができる。エクスポートはダウンロードとテキスト出力に対応する。インポート先は現在のプロフィールで、書き出し元のユーザー ID は引き継がない
- ローカルに 1 秒ごと、Tonarium サーバーに 30 秒ごとに保存する。サーバーとの通信に失敗してもローカル保存は続く。再開時には最大 8 時間のオフライン進行を計算する。サーバーからの読込は現在のローカル進行を上書きするため、確認が出る

セーブは Tonarium アプリ内で完結する。サーバーのセーブとランキングは、ログインしたアカウントごとに 1 つ（DB の `app_data` の `ad.save`・`ad.leaderboard`。キーはアカウント ID）。`GET/POST /api/save/:playerId` と `POST /api/leaderboard` は URL や本文の playerId・名前を使わず、ログインの本人で読み書きするので、他人のセーブは読み書きできない。画面のプロフィールを切り替えても、サーバーに残るのはアカウントの 1 つだけ。ランキングの名前は名簿の表示名で、上位 50 件を返す。既定は同一オリジンの Tonarium サーバーで、Cloudflare Workers は不要。`VITE_AD_API_BASE` で API の接続先を上書きできる。

ゲストのサーバー保存とスコア送信は 403 になり、画面は「ゲストの進行はこの端末にだけ保存されます」と出してローカルで続ける。バックアップや移行には v2 エクスポートを使える。

## お絵描き伝言

「出す」から置いたアイテムごとに参加登録する。在席している登録者が2〜30人のときに開始でき、初回はその中の誰でも開始できる。開始者が王冠付きのホストになる。開始時の登録順で参加者を固定し、途中参加・登録は次回待機となる。登録解除や退室で今回の順序や担当は変わらない。

人数と同じ数のチェーンを同時進行し、文章から始めて描画と交互に、人数と同じ工程数を行う。参加者番号を i、工程を s、人数を N とすると担当チェーンは `(i - s + N) % N`。各人が各チェーンを一度ずつ担当する。文章は初回も絵の説明も60秒、描画は120秒。全員が提出した時点、または締切で一度だけ進む。期限内の提出は変更できず、未提出は空回答・白紙になる。文章は1000文字、絵は620×450座標・250ストローク・2000点まで。線は6色と消しゴム、太さ3段階で描ける。

切断・退室・全員不在でもサーバーが締切を処理する。同じユーザーIDで復帰すると、現在の担当と直前の伝言・提出済み回答を再取得できる。ホストが不在または登録解除した場合、在席登録者（次回待機中の人も含む）からランダムで引き継ぐ。候補者がいない間はホストなしで進み、候補者が戻ると引き継ぐ。進行中は全員に再開始を禁止する。

終了後はホストが「次の回答を公開」でチェーン順・工程順に一つずつ公開する。「前へ」「次へ」で公開済みページを移動でき、全閲覧者に同じ公開状態とページを配信する。未登録者や途中参加者も工程・残り時間・参加者と公開済み結果を閲覧できる。結果鑑賞中の次回開始は在席登録者のホストだけに許可する。ホスト不在時に限り、在席登録者の誰でも人数条件を満たして開始できる。次回の開始者が新しいホストとなり、前回の全回答・公開状態・ページをリセットする。開始に失敗した場合は履歴を残す。

進行状態と回答はアイテムと一緒に DB の `session_items` に保存し、保持期限を設けない。開始済みのゲームがあるユーザー作成セッションは、無人5分による自動削除の対象から外す。明示的なアイテムの片付け、全アイテムを消すワールド切替、セッション削除では履歴も消える。サーバー再起動時は保存済みの締切から経過工程を処理する。

公開用の型・割当計算は `shared/telephone.ts`、人間の登録・ホスト選択と、工程進行・提出はそれぞれ `server/telephone.ts` の別関数で扱う。AI の登録・操作は実装しない。保存用の `telephoneState` はサーバー専用で、通常更新も復帰スナップショットも閲覧者別の `telephoneItemFor` を通す。進行中は本人の現工程の提出と、担当チェーンの直前一件だけを渡す。終了後も未公開回答を渡さず、公開済み結果だけを渡す。提出をP2Pイベントやチャットには流さない。

受け入れロジックのテストは `npm run test:telephone`。人数境界（1・2・30・31）、全人数の循環割当、時間制限、二重提出と締切競合、全員不在・保存からの復帰、ホスト引継ぎ、次回開始権限、閲覧者別の配信制限、結果公開・ページ同期、履歴保持とリセットを検証する。

## バイク

マーケットの「バイク」を購入すると、既存の所有アイテム一覧から取り出せる。価格は150。既存アイテム商品（100〜150）に合わせ、おしゃべりカードと同額を推奨値とした。購入と所有状態の保存は既存の `purchaseProduct` とユーザー別のブラウザ保存を使う。置いたバイクは誰でも乗れる。

3D の地上で3m以内に近づき、照準を合わせて E またはクリックで乗車する。W/↑でアクセル、S/↓でブレーキ、A/D・←/→でハンドル、Eで降車。乗車中は照準の操作ヒントが運転操作に切り替わる。アイテム説明ウィンドウでも確認できる。マウスでは上下の視点だけを動かし、左右の向きはハンドルで変える。Eで降りる際は最後の走行位置を送ってから停止する。降車後は通常の歩行とジャンプに戻る。空車は右クリックで運び、Xで片付けられる。乗車中の持ち運び・片付けは拒否する。

`shared/vehicle.ts` の純粋関数に、前の状態、アクセル・ブレーキ・ハンドル、秒単位の dt を渡す。1/120秒刻みで更新し、余りは次へ持ち越す。速度とホイールベース・舵角から旋回速度を求め、横加速度に応じて内側へ傾ける。グリップを超えると車体の向きに進行方向が追いつかず、追加の抵抗で減速する。車輪の回転角は移動距離÷車輪半径で進める。

| 定数 | 値 | 意味 |
| --- | --- | --- |
| step | 1/120 s | 固定ステップ |
| maxSpeed | 10 m/s | 最高速（36 km/h） |
| acceleration | 3.5 m/s² | アクセルの加速 |
| braking | 7 m/s² | ブレーキの減速 |
| drag | 0.35 m/s² | 常時の抵抗 |
| wheelbase | 1.3 m | 前後輪の距離 |
| wheelRadius | 0.32 m | 車輪半径 |
| maxSteer | 0.55 rad | 最大舵角 |
| grip | 5 m/s² | 滑り始める横加速度 |
| leanFactor | 1 | atan(横加速度/9.81)への係数 |
| maxLean | 0.65 rad | 傾きの上限 |
| leanResponse | 8 /s | 傾きの追従速度 |
| skidDrag | 1.8 m/s² | 滑走中の追加減速 |
| radius | 0.9 m | 衝突判定の円の半径 |

乗車の先着順と乗車者IDはサーバーが確定する。一人で複数台には乗れない。走行状態は乗車者が20Hzで既存の `itemAction` 経路へ送り、サーバーが乗車者と乗車番号を確認して `item` として共有・保存する。他のクライアントは位置・向き・傾きを補間表示する。降車・切断・2Dへの切り替え・退出・ワールド切り替え・サーバー再起動で空車に戻す。

対応は地上の簡易走行のみ。後退、二人乗り、ジャンプ、転倒、坂道・階段・建物の上階・電車内の走行、実車のサスペンションやタイヤ計算には対応しない。描画が止まる長いフレームは0.25秒まで計算する。壁・家具・街の地上障害物・境界は既存の `pushOut` と境界制限を各固定ステップで使い、接触時に停止する。専用の物理エンジンは使わない。走行の正当性をサーバーで再計算する仕組みや不正運転対策は含まない。

効果音の取得状況は [素材記録](assets.md)、検証の実施状況と残る手順は [バイクの検証記録](bike-verification.md) を参照。現時点では音声素材を同梱できておらず、バイクの効果音は鳴らない。

### 画像の3D配置

画像には台がなく、表示面の中心を任意の高さへ移動できる。アイテムに照準を合わせて右クリックすると配置を開始し、視点の位置と視線方向、視点からの距離に従って実物がプレビューとして動く。視線を上下左右へ向けて床上や空中へ移動し、右クリックまたは左クリックで確定する。床上に置く場合は下辺を床へ合わせる。床や壁への自動吸着・衝突補正はなく、床下や壁の中にも置けるのでプレビューを確認して確定する。

- 配置中のホイール：下へ回すと遠く、上へ回すと近くなる（1段階0.25m、初期距離2.2m、範囲0.5〜20m）。
- 配置中のShift＋ホイール：上へ回すと拡大、下へ回すと縮小する。縦横比と表示面の中心、視点からの距離は変わらない。倍率は元の表示サイズの0.1〜10倍。元の表示サイズは幅1.8m・高さ1.3mの枠内に縦横比を保って収めた大きさ。
- 配置中のホイールはカメラのズームやページスクロールに使わない。配置を終えると通常の操作へ戻る。画像以外の運搬操作は従来どおり。
- 高さは表示面の中心で−100〜100m、水平位置は既存のワールド範囲内。境界では座標を制限するため、視線上の計算位置からずれることがある。表示面の向きは水平方向の視線に合わせ、面は垂直のまま配置する。
- 確定したX/Y/Z座標・向き・倍率は既存のアイテム移動経路で全員に配信し、アイテムと一緒に保存する。配置中も約80ms間隔で共有する。旧データで高さ・倍率がない画像は中心高さ1.6m・倍率1で表示する。再配置の開始距離は毎回2.2m、倍率は前回の値を引き継ぐ。
- YouTubeは今回の距離・サイズ調整の対象外で、従来の台と表示を使う。2Dウィンドウのサイズはこの3D倍率では変わらない。

回帰テストは `npm run test:media-placement`。視線による床上・空中の座標、距離変更、距離と中心を保った縦長・横長の等比拡縮、上下限・不正値、画像の共有メッセージ形式とJSON保存での座標・倍率の保持、三人称カメラと配置プレビューの干渉を対象にする。これは実際の複数クライアント接続やWebGL描画の検証には代わらない。

### 添付と再生

- Ctrl+V かドラッグ＆ドロップで、画像（JPEG/PNG/GIF/WebP、10MB まで）・YouTube のリンクを共有できる。3D では目の前にアイテムとして出てチャットにも投稿され、2D ではチャットに投稿だけされる。大きすぎるものは送る前に断る（サーバーでも同じ上限を見る）。メニューからホームを重ねている間は受け取らない（タイムラインのページならポストの写真になる。ほかのページでは落としたファイルを無視して、窓で開かないようにする）
- チャット欄の添付ボタンからも画像を送れる。チャットの画像・YouTube には「アイテムにする」ボタンがあり、押すと目の前に出る
- Web版の3D画像アイテムはGIFの各フレームを表示時間どおりに再生し、最終フレームの後は先頭へ戻って繰り返す。再生位置は端末ごとで、チャット欄のGIFとは独立している。静止画像は通常の画像テクスチャで表示する。
- ファイルはサーバーの `data/media/` に保存され、合計 1GB を超えたら古いものから消える
- YouTube はみんなで同じところを再生する（再生・一時停止・シークは全員に反映）。ウィンドウの下の操作バー、または 3D で板をクリックで操作する。音は 3D では距離で小さくなり、2D ではウィンドウを開いているときだけ鳴る。操作バーの音量は自分だけに効き、最初は半分（アイテムごと。再読み込みで半分に戻る）
- YouTube は他サイトの動画なので 3D の板にテクスチャとして貼れない。本物のプレーヤーを板の位置・傾きに合わせて HTML で重ねている（手前の物に隠れない・裏側からは見えない）

GIFは `client/src/view3d/imageTexture.ts` で `gifuct-js` を使ってデコードし、`gifPlayback.ts` で差分フレーム・透明色・消去と復元を合成する。全フレームを展開して保持するため、デコード前に論理画面（1024×1024 まで）・フレーム数（600 まで）・全フレームのピクセル数合計（64M まで）を `gifWithinLimits` で確認し、超える場合はアニメーションせず静止画として表示する。3Dの描画フレームから表示時間を進め、画像が変わったときだけテクスチャを更新する。GIF内の繰り返し回数指定にかかわらず、アイテムは継続してループする。削除・URL変更・3D画面からの離脱で読み込みを中断し、フレームデータ・キャンバス・テクスチャを解放する。チャットと2Dウィンドウは従来の画像要素を使う。

回帰テストは `npm run test:gif`。フレーム順序と待ち時間、複数周のループ、透明差分、消去・復元、静止画読み込み、読み込み途中の削除と解放を確認する。実画面では、動くGIFをチャットに投稿して「アイテムにする」を押し、3Dの板とチャットの双方で3周以上動くことを確認する。JPEG/PNG/WebPもアイテム化して表示・縦横比を確認し、GIFアイテムを削除してチャット側の再生が続くことを確認する。
