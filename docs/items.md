# アイテムとメディア共有

アイテムの定義は `shared/items.ts`（状態・操作・リストに出すマークと色）、2D 画面はキャンバスで描くものが `client/src/items/panels.ts`、React で作るウィンドウが `client/src/world/`（サイコロは `DiceBody.tsx`）、3D 表示は `client/src/view3d/items3d.tsx`。

## 同期と保存

- 移動の同期は位置だけの軽量メッセージ（`itemMove`）で、中身は含めない。作成・内容の更新・削除はアイテム全体を配る（同期の詳細は `docs/sync.md`）
- アイテムは `data/items.json` に保存され、再起動しても戻る。保存は 5 秒ごとの確認で、変更があったときだけ書き出す
- 付箋（2D/3D）: 2D ではウィンドウ、3D では空間内の看板。編集中は他の人に「編集中」と出る
- ピコピコハンマー（2D/3D）: 1本につき1人が持てる。3D では照準で拾い、アバターや 2D の人を叩く。2D では「手に持つ」→ マウスのところにハンマーが出て、リストや顔の人をクリックで叩き、相手のすぐそばに移る
- チェス（2D/3D）: クリックで駒を選び、もう一度クリックで移動。ルールは下の「チェス」
- サイコロ（2D/3D）: TRPG 用。ウィンドウで種類（d4・d6・d8・d10・d12・d20・d100）と個数（1〜10）を選んで振る。結果はサーバーが決め、全員が同じ転がり方を見る（3D は木の器の中を転がり、2D はくるくる回る）。転がり終わるとチャットに記録される。「シークレット」で振ると結果は本人にだけ見え、ほかの人には振ったことだけが伝わる。3D では器をクリックすると、最後にウィンドウで選んだ設定で振る
- キャンバス（2D/3D）: みんなで絵を描ける。ペン（6色・細/太）、消しゴム、全部消す、保存（ログに画像で投稿）
- カメラ（3D 専用）: 持っている間はファインダー表示でクリック = 撮影、L = ライブ配信、Q = 三脚に置く。三脚のカメラは照準で C = 撮影、L = 配信。写真はログに投稿される。ライブは 2D ではウィンドウ、3D ではカメラの上のモニターに映る
- 2048（2D 専用）: 全員で1つの盤面を操作。いちばん前のウィンドウなら矢印キーでも動かせる。3D では互換モードとして 2D 画面がパネルで置かれる
- AD ポータル（2D/3D）: どのワールドにも置ける、自分の反物質次元を開く入口。2D では近くのリストやマップから、3D ではミニチュア研究所に照準を合わせてクリックして開く。3D では右クリックで持ち運び、X で片付けられる。進行は自分のプロフィールごとに保存され、複数のポータルから同じ進行を開ける
- バイク（3D 専用）: マーケットで購入し、所有アイテムから出す。一人乗り。操作とモデルは下記。

## AD ポータルと研究所パネル

次元を買って反物質を増やす個人用のゲーム。ポータルを片付けたり、ワールドを切り替えたり、セッションを退出したりしても進行は残る。[AD 研究所ワールド](3d.md#ad-研究所) では同じ進行が空間内の装置に反映される。

- 「次元」で第 1 次元から購入する。「1個買う」「10個まで買う」と Tickspeed、Max All を使える。次元カードには所持量・購入数・生産量・倍率・コストと、動くリアクターが出る
- 「Boost / 銀河 / Sacrifice / Crunch」で条件とリセット内容を確認して進める。Big Crunch までが操作対象で、以降のレイヤーは説明・モック表示。「統計・実績・ランキング」から進行を確認し、名前を付けてスコアを送れる
- 内容が縦に収まらないときは研究所パネルの中をスクロールする。狭いウィンドウでは購入ボタンが次の行に並ぶ。ボタンのホバー・キーボードフォーカス・無効状態の見た目は、このパネル内に適用される
- 操作成功時に、購入した次元やコアのイラストの周りで小さな粒子が広がり、操作音が鳴る。音量はドックの音量メニューの「サウンドボード・効果音」で調整できる。OS のアニメーション軽減設定に従い、リアクターの回転と購入時の粒子を止める
- 「プロフィール・セーブ」でプロフィールの作成・切替・削除、サーバー保存・読込、最初からのリセット、v2 JSON のエクスポート・インポートができる。エクスポートはダウンロードとテキスト出力に対応する。インポート先は現在のプロフィールで、書き出し元のユーザー ID は引き継がない
- ローカルに 1 秒ごと、Tonarium サーバーに 30 秒ごとに保存する。サーバーとの通信に失敗してもローカル保存は続く。再開時には最大 8 時間のオフライン進行を計算する。サーバーからの読込は現在のローカル進行を上書きするため、確認が出る

セーブは Tonarium アプリ内で完結する。`GET/POST /api/save/:playerId` は `data/ad-saves.json`、`GET/POST /api/leaderboard` は `data/ad-leaderboard.json` を使い、セッションの `data/items.json` 等とは別に保存する。既定は同一オリジンの Tonarium サーバーで、Cloudflare Workers は不要。`VITE_AD_API_BASE` で API の接続先を上書きできる。

Tonarium にはアカウント認証がなく、サーバーは URL の playerId を保存キーとして受け入れる。他人のセーブへのアクセスを防ぐ 403 保護はない。バックアップや移行には v2 エクスポートを使える。

## バイク

マーケットの「バイク」を購入すると、既存の所有アイテム一覧から取り出せる。価格は150。既存アイテム商品（100〜150）に合わせ、おしゃべりカードと同額を推奨値とした。購入と所有状態の保存は既存の `purchaseProduct` とユーザー別のブラウザ保存を使う。置いたバイクは誰でも乗れる。

3D の地上で3m以内に近づき、照準を合わせて E またはクリックで乗車する。W/↑でアクセル、S/↓でブレーキ、A/D・←/→でハンドル、Eで降車。乗車中は照準の操作ヒントが運転操作に切り替わる。アイテム説明ウィンドウでも確認できる。マウスでは上下の視点だけを動かし、左右の向きはハンドルで変える。Eで降りる際は最後の走行位置を送ってから停止する。降車後は通常の歩行とジャンプに戻る。空車は右クリックで運び、Xで片付けられる。乗車中の持ち運び・片付けは拒否する。

`shared/vehicle.ts` の純粋関数に、前の状態、アクセル・ブレーキ・ハンドル、秒単位の dt を渡す。1/120秒刻みで更新し、余りは次へ持ち越す。速度とホイールベース・舵角から旋回速度を求め、横加速度に応じて内側へ傾ける。グリップを超えると車体の向きに進行方向が追いつかず、追加の抵抗で減速する。車輪の回転角は移動距離÷車輪半径で進める。

| 定数 | 値 | 意味 |
| --- | --- | --- |
| step | 1/120 s | 固定ステップ |
| maxSpeed | 10 m/s | 最高速（36 km/h） |
| acceleration | 3.5 m/s² | アクセルの加速 |
| braking | 7 m/s² | ブレーキの減速 |
| drag | 0.35 m/s² | 常時の抵抗 |
| wheelbase | 1.3 m | 前後輪の距離 |
| wheelRadius | 0.32 m | 車輪半径 |
| maxSteer | 0.55 rad | 最大舵角 |
| grip | 5 m/s² | 滑り始める横加速度 |
| leanFactor | 1 | atan(横加速度/9.81)への係数 |
| maxLean | 0.65 rad | 傾きの上限 |
| leanResponse | 8 /s | 傾きの追従速度 |
| skidDrag | 1.8 m/s² | 滑走中の追加減速 |
| radius | 0.9 m | 衝突判定の円の半径 |

乗車の先着順と乗車者IDはサーバーが確定する。一人で複数台には乗れない。走行状態は乗車者が20Hzで既存の `itemAction` 経路へ送り、サーバーが乗車者と乗車番号を確認して `item` として共有・保存する。他のクライアントは位置・向き・傾きを補間表示する。降車・切断・2Dへの切り替え・退出・ワールド切り替え・サーバー再起動で空車に戻す。

対応は地上の簡易走行のみ。後退、二人乗り、ジャンプ、転倒、坂道・階段・建物の上階・電車内の走行、実車のサスペンションやタイヤ計算には対応しない。描画が止まる長いフレームは0.25秒まで計算する。壁・家具・街の地上障害物・境界は既存の `pushOut` と境界制限を各固定ステップで使い、接触時に停止する。専用の物理エンジンは使わない。走行の正当性をサーバーで再計算する仕組みや不正運転対策は含まない。

効果音の取得状況は [素材記録](assets.md)、検証の実施状況と残る手順は [バイクの検証記録](bike-verification.md) を参照。現時点では音声素材を同梱できておらず、バイクの効果音は鳴らない。

## チェス
- 白から交互に指す共有盤です。参加登録や席の割り当てはなく、手番の色の駒を誰でも動かせます。
- 駒を選ぶと合法な移動先が表示されます。チェックを放置する手や、自分のキングを危険にさらす手は指せません。
- キャスリング、アンパッサン、4種類から選ぶ昇格に対応。チェックメイト、ステイルメイト、戦力不足、50手ルール、同一局面3回を判定します（引き分けは申告なしで自動終了）。
- 2D は手番・チェック・結果・直近の棋譜を表示。3D でも移動先・手番・結果・昇格の選択を表示します。「新しい対局」を2回押すと初期化します。
- サーバーが合法手と盤面の更新番号を確認し、全員に結果を配信します。同時操作のうち古い盤面に対する操作は反映しません。
- ルールの回帰テスト: `npm run test:chess`。ルール判定には [chess.js](https://github.com/jhlywa/chess.js) を使用しています。

## チェスAI
- 「出す」から「チェスAI」を選ぶと、共有チェスとは別のAI対戦盤を置けます。2D・3Dの両方に対応しています。
- 白は誰でも操作でき、黒はサーバーのAIが自動で指します。参加登録・外部API・APIキーは不要です。
- AIは駒の価値や展開を評価し、時間制限内で最大3手先まで探索する軽量版です。考慮中は表示が切り替わり、黒の駒を手動では動かせません。
- 昇格や勝敗判定は共有チェスと同じです。考慮中のリセット・片付けでは、古い応手を破棄します。

## 画像・動画・YouTube の共有
- Ctrl+V かドラッグ＆ドロップで、画像（JPEG/PNG/GIF/WebP、10MB まで）・動画（MP4/WebM、50MB まで）・YouTube のリンクを共有できる。3D では目の前にアイテムとして出てチャットにも投稿され、2D ではチャットに投稿だけされる。大きすぎるものは送る前に断る（サーバーでも同じ上限を見る）
- チャット欄の添付ボタンからも画像・動画を送れる。チャットの画像・動画・YouTube には「アイテムにする」ボタンがあり、押すと目の前に出る
- ファイルはサーバーの `data/media/` に保存され、合計 1GB を超えたら古いものから消える
- 動画と YouTube はみんなで同じところを再生する（再生・一時停止・シークは全員に反映）。ウィンドウの下の操作バー、または 3D で板をクリックで操作する。音は 3D では距離で小さくなり、2D ではウィンドウを開いているときだけ鳴る。操作バーの音量は自分だけに効き、最初は半分（アイテムごと。再読み込みで半分に戻る）
- YouTube は他サイトの動画なので 3D の板にテクスチャとして貼れない。本物のプレーヤーを板の位置・傾きに合わせて HTML で重ねている（手前の物に隠れない・裏側からは見えない）
