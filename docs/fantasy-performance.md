# RPG 로딩·서버 처리 최적화

게임 수치·가격·재고·행동·권한·저장 구조를 유지하면서 실제로 반복되던 계산과 초기 화면 로딩을 줄였다. Tonarium 본체와 외부 KokoaAI 연결 방식은 변경하지 않는다.

## 서버 처리

`fantasyBuildingStock`은 요청한 시설의 상품만 구성하고, 같은 호출에서 품목을 반복 탐색하지 않는다. 경제 저장 검증은 시설별 허용 목록을 한 번 구성하며, 모든 상품·수량·기한·권한 검사는 유지한다. 거래 화면은 한 요청 안에서 시설·재고 스냅샷을 재사용하고 표시 가격과 판매 그룹을 중복 계산하지 않는다.

이 재사용은 각 함수 호출이 끝나면 폐기된다. 플레이어·권한·가격·재고·날짜별 결과를 전역에 저장하지 않으므로 다음 요청에는 재고 감소·할인·이동·식품 기한 변경을 다시 반영한다. 명단의 첫 항목을 선택하는 기존 동작과 상품 순서도 유지한다.

같은 Node24.22.1·강제 GC 옵션·6회 표본으로 이전 커밋의 격리된 소스와 개선 코드를 비교했다. 상점96개와 경제 상황6개의 직렬화 결과도 개선 전후 완전히 같다.

| 로컬 처리 | 이전 중앙값 | 개선 후 중앙값 | 감소 |
| --- | ---: | ---: | ---: |
| 재고 동기화 |13.13ms|2.70ms|약79%|
| 거래 화면 구성 |42.31ms|7.63ms|약82%|
| 경제 저장 검증 |504.82ms|7.20ms|약99%|

CPU 프로파일에서 시설 상품 목록을 상품마다 재구성하는 부분이 가장 큰 병목이었다. 이 수치는 Node 안의 해당 함수 처리 시간이며 운영 서버의 네트워크·DB 대기·전체 응답 시간이나 AI 추론 시간을 나타내지 않는다. 강제 GC 뒤 유지 힙은 약28.6→27.9MB로 비슷한 수준이다. 프로세스 피크 RSS는 초기 로딩·트랜스파일러·GC 영향을 받으므로 큰 메모리 절감으로 해석하지 않는다.

## 화면 로딩

17개 보조 패널은 필요한 메뉴를 열 때 불러온다. 마을·소지품·장비·의뢰·파티·부동산·거래·신앙·합성·GM·랭킹·전투 등이 대상이며 일부는 같은 코드 묶음을 공유한다. 일반 지도와 메뉴 탐색은 계속 표시한다. 전투 오류 문구와 거래 명령 전송 함수를 큰 UI에서 분리하여 이 함수만 쓰는 화면이 전투 연출이나 거래 화면 전체를 불러오지 않게 했다.

초기 RPG 추가 JavaScript는 같은 빌드 분석 조건에서1,251,562→864,451바이트로 약31% 줄었다. 이 값은 이미 로드된 Tonarium 진입 코드의 정적 의존성을 제외하고 RPG에 추가로 필요한 정적 코드 묶음을 합산한 압축 전 크기다. 파일 하나만 비교한 수치가 아니다. 호스트 초기 정적 코드는3,884,343→3,883,327바이트로 늘어나지 않았다. 기존 대용량 청크 경고는 남아 있다.

지연 로딩 중에는 세 언어의 짧은 상태 문구를 표시한다. 실패하면 기존 메뉴 오류 화면에서 재시도할 수 있으며, 재시도할 때만 실패한 React.lazy 캐시를 새로 만든다. 코드만 지연 로딩하며 플레이어 데이터나 대화 내용을 이 캐시에 넣지 않는다. 실제 HTTP 모듈 요청을 한 번 중단한 뒤 재시도가 두 번째 요청으로 성공하고 지도·탐색이 유지되는 것을 확인했다. 성공한 재시도 타입을 재방문에도 사용하므로 메뉴를 닫았다 다시 열 때 이전 실패 캐시로 돌아가지 않는다.

## 재측정

```sh
npm run benchmark:fantasy -- --iterations=8 --output=work/qa/fantasy-performance/report.json
```

이 명령은 임시 인물과 재고를 메모리에서 만들고 동기화·표시·검증 시간, 결과 지문, 힙과 RSS를 기록한다. 실제 계정·진행도·DB·외부 AI를 읽거나 변경하지 않고 서버 포트를 열지 않는다. 표본 수는1~100이며 기기별 시간 변동이 있으므로 단위 테스트에서 절대 시간 제한을 강제하지 않는다.

## 검증 기록

- 공유 게임 로직1411/1411, 클라이언트99/99, RPG UI50/50, 서버 거래·권한·저장 실패41/41, 측정 도구1/1 통과.
- 메뉴16종과 전투 조작7개, 실제 필요한 시점의 모듈 요청, 세 언어 로딩, 지연 중 인물 변경, 로딩 실패 재시도를 브라우저에서 확인했다.
- 타입 검사·프로덕션 빌드 및 별도 도구 타입 검사를 통과했다. 별도 읽기 전용 코드 검토에서 수정할 결함이 없었다.
- 프로파일·이전/이후 측정 JSON·전체 결과 비교·브라우저 기록은 `work/qa/fantasy-performance/`에 보존한다. 임시 확인 서버와 탭은 종료했다.
- 실제 운영 서버의 장시간 플레이·다중 접속·외부 AI 품질은 기존 방침대로 배포 후 로그로 확인한다. PR391은 Draft 유지, 자동 병합·배포 없음.
