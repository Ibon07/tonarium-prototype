## 실제로 확인한 조리 동작

- 고정 요리 48종을 각각 실제 생성해 다섯 재료의 정확한 소모, 고유 결과1개, 제조 시각을 확인했다. 신규 음식114종·재료19종의 세 언어 이름·설명 및 중복 이름을 확인했다.
- 자유 요리22계열의 각 세 후보, 총66개 결과를 실제 생성했다. 정상20계열/위험2계열, 추가 재료의 연결·가중치, 같은 재료의 중복 칸, 여섯 단위·잘못된 연결 거절을 확인했다.
- 재고/장작/마법사 점화에 따른 반복 상한, 진행 경계별 생성, 실패·독성·부패·식품 보존, 정상 성공만 의뢰 실적 인정, 중도 취소·재접속·저장 복구를 확인했다.
- 소유자/공동 이용자의 동시 조리, 공유 재고 선점, 임대 만료, 직원 생산과의 시간 순서, 저장 실패와 되돌리기, 128개 완료 시각 단계 뒤 체크포인트·재시작·남은 작업 재개를 확인했다.
- **실제 서버와 WebSocket 세 접속**을 사용한 회귀를 `server/fantasy-cooking-ws.test.ts`로 정식 등록했다. 직접 새로고침 요청 없이 조리 완료 재고를 받아 공동 이용자의 실제 조리 화면 상한이 **3→2→0**으로 바뀌며, 관계없는 관찰자는 창고 재고·식품 묶음 식별자를 받지 않음을 확인했다. 이 검사는 최종1,584건에 포함된다.
- 부동산 관련199건과 독립 경계22건도 수정 과정에서 통과했다. 최종 전체 검사와 중복되므로 별도 총합으로 과장하지 않는다.
- 음식 시각 보정은 새 캐릭터 생성 시 적용하는 경로다. 기존 캐릭터의 음식 이력을 로딩 중 임의로 음수 이동시키지 않음을 추가 확인했다.

## 검사에서 발견하여 수정한 실제 문제

1. **소수 시각의 조리 시작 실패**: `15.1+3-15.1`의 부동소수 오차를 기간 위조로 오인하던 비교에 기존 시간 허용 오차를 적용했다.
2. **임대 작업장의 권한 시점 오류**: 완성 시각에 다시 조리 시간을 더해 권한을 검사해, 유효한19–22시 작업이24시 임대 종료 전에 취소되던 문제를 수정했다. 늦게 한 번 동기화해도 종료 전 완성품은 보존하고 이후 회차는 소모하지 않는다.
3. **공유 창고의 시간 순서**: 나중 직원 생산이 먼저 끝난 플레이어의 재료를 가져가거나, 한 사용자의 미래 반복을 다른 사용자의 과거 반복보다 먼저 정산하던 처리를 완료 시각 순서로 바꿨다. 같은 시각의 직원 우선순위와 기존 직원12구간 상한을 유지한다.
4. **추격 처리 후 미래 재고 선반영**: 128단계 상한 뒤 남은 작업이 있으면 체크포인트를 보존한다. 다른 저장·새 창고 작업이 미정산 시간대를 뛰어넘지 않도록 제한했다.
5. **파티 창고·전투 경로의 조리 유실**: 조리 재료 접근 문맥 없이 파티원을 진행시키던 별도 경로가 조리 대기열을 지우지 않게 했다. 공용 엔진도 재료가 필요한 시점에 창고 문맥이 없으면 원본과 대기열을 보존한 채 오류를 반환한다.
6. **즉시 반복 제작의 의뢰 실적 누락**: 내부 즉시 처리 경로도 회차별 정상 마무리를 거쳐 두 번 성공은 실적2, 한 번 실패는 실적1이 되게 했다. 정상 서버 예약 경로와 일치한다.
7. **새 식재료 ‘배’가 한국어 질문을 가로챔**: ‘배울 수 있어?’를 과일 질문으로 읽던 문자열 일치 문제를 수정했다. ‘배가격’, ‘배는 몇개’ 등 실제 상품 질문과 조사가 붙은 형태는 유지한다. 실제 배 재고가 있는 시설에서도 기술 안내가 정상임을 확인했다.

원인 재현 후 수정한 경계 사례의 실패/성공 로그도 보관했다. 새로운 의미에 맞지 않는 검사 기대값은 따로 수정했다: 부패 재료는 거부하는 대신 해로운 음식이 되어야 하며, 사제 분기에는 새 전용 성속성 공격이 있고, 책상·서랍 추가 후 가구 용량은10이다. 다른 분기의 미습득 기술은 화면 전체와 전투 기술 집합에서 계속 숨겨짐을 확인한다. 저장 규칙과 맞지 않던 임대/공동명의 테스트 자료와 누락된 검사 참조도 수정했다.

## 화면 검사의 범위

실제 조리 컴포넌트와 스타일을 격리 페이지에서 조작했다. 다섯 한 개짜리 칸, 후보 세 이름과 확률, 같은 주재료에 추가 재료 중복 연결 방지, 반복 수 제한·소수 입력 거절, 재고 소실·창고 권한 소멸의 비활성 이유, 긴 영문 음식명이320px에서 줄바꿈되는 것을 확인했다. 서버 저장·공동 재고는 별도 실제 WebSocket 검사로 연결했다.

전체 게임의 주변 패널·실물 모바일 터치·운영자 계정/HTTPS/실제 AI 문장 품질까지 이 격리 화면 검사로 확인했다고 주장하지 않는다. PC에서는 주재료 선택 칸이 추가 재료 카드 높이에 맞춰 길어지는 사소한 시각적 여지가 남지만 조작이나 글자 표시를 막지는 않았다. Vite의 기존 큰 청크·동적/정적 import 혼용 경고는 경고이며 최종 빌드는 종료0이다.

## 아직 남은 작업

- **기존 전투 균형 미달은 그대로 남아 있다.** 본 검증에서 몬스터/직업 수치를 다시 조정하거나 대규모 승률 모의전을 다시 돌리지는 않았다. 이전 실측의7급 대7급33.51%(목표35–45),8급 대7급67.14%(목표55–65)와 직업별 편차는 [전투 실측 기록](fantasy-combat-measurement-2026-10-30.md)을 따른다. 핵심 몬스터·파티·직업·전투 네 파일의 해시는 이전 검사와 같지만, 이를 새로운 승률 측정으로 바꾸어 표현하지 않는다.
- 운영 배포 후 실제 이용자의 장시간 플레이·다인 접속·단절/지연·자유 대화 품질은 서버 로그와 함께 확인해야 한다. 이번 KokoaAI 검사는 모의 서버·응답을 사용하는 코드 검증이며 운영 API의 현재 상태를 확인한 결과가 아니다.
- 과거 상세 체크리스트에는 수동 전술·운영 조건이 섞여 있다. 이번 자동 검사 통과를 이유로 이전의 모든 체크박스를 일괄 완료 처리하지 않는다.

검사는 임시 디렉터리의 합성 저장·테스트 서버·가짜 시계만 사용했다. 실사용 저장 파일·실계정·배포 환경변수는 수정하지 않았고 임시 서버와 브라우저는 종료했다.
