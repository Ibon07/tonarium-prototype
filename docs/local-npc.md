# ローカル NPC 自由会話

韓国語・英語・日本語で NPC に自然文を送る短いプロトタイプ。公開設定に答える部分と、運営側のローカルモデルが生成する雑談を組み合わせる。返答には「設定情報」と「ローカル AI」の出典を表示し、すべてをモデルが生成したようには扱わない。

開始画面とアプリ右上の言語選択は共通で、画面と会話の言語を切り替える。現在のゲーム確認入口は [RPG プロトタイプ](http://127.0.0.1:5183/?rpg=1)。通常のログイン後に「はじめる」を押すと、自分用の非公開（招待制）ファンタジーセッションを作成して参加する。ゲーム内では現在地の建物に入り、そこにいる NPC へ話しかける。既定の 3 セッションは変更しない。

NPC 会話だけを試す独立した確認画面も `?npc=1` に残している。クライアントが 5183 の場合は [NPC 単独確認](http://127.0.0.1:5183/?npc=1)。生成に失敗した場合はエラーを表示し、失敗を固定の AI 返答で隠さない。

RPG 内では大きな会話ウィンドウを開き、デスクトップでは約 880×760、狭い画面では画面いっぱいに表示する。最小化と閉じるは会話を消さず、別メニューを開いても履歴を保つ。同じ NPC に戻れば続きを話せる。「新しい会話」で記録を消すボタンは削除した。別の NPC の会話は混ぜず、現在地を離れた相手とは会話を続けない。

会話の人物欄には名前・職業・地域と年齢・性別・種族を表示する。性格の説明、話し方、得意分野、プレイヤーとの関係の一覧は表示しない。これらの設定と関係の判定は、内部の会話生成・情報公開条件に引き続き使う。

| ID | 한국어 / English / 日本語 | 公開プロフィール |
| --- | --- | --- |
| `rin` | 린 / Rin / リン | 34歳・女性。元行商人で、穏やかで親しみやすい宿の主人 |
| `borin` | 보린 / Borin / ボリン | 52歳・男性。無口で実用性を大切にする山ドワーフの鍛冶師 |
| `eris` | 에리스 / Eris / エリス | 27歳・女性。記録と推測を区別する慎重な学者・記録係 |

上記 3 人に各地の住人を加え、公開プロフィールを持つ NPC は **62 人**。所属する大陸・地域、種族、暮らし、専門分野と教えられる職業・技を登録している。全員の一覧は `shared/npc.ts` と `shared/npc-residents.ts` を参照する。居住地の NPC は特定の店舗に属さない場合もある。NPC の返答本文からゲーム内の金貨、アイテム、依頼、能力、ダイス結果を変更する機能はない。モデルにファイル、シェル、ゲーム操作などのツールも渡していない。

## 接続の流れ

```text
Web 画面 → Tonarium サーバー → 同じ運営環境の llama.cpp → Qwen3
```

ブラウザはモデルへ直接接続しない。外部の有料生成 API や API キーを使わず、会話の生成は運営側の CPU と RAM を使う。最初の実行ファイル・モデルのダウンロードにはインターネット接続が必要だが、会話のたびに外部生成サービスへ問い合わせる構成ではない。

今回の実行環境は Windows x64、CPU は Ryzen 7 5800X、RAM は約 16GiB。`llama.cpp b11856` の CPU 版と、Qwen 公式の `Qwen3-1.7B-Q8_0.gguf` を使う。GPU 用のドライバーや大型の実行環境、Python パッケージ、Docker、Ollama のシステムインストールは追加しない。

## 実行

プロジェクトルートで PowerShell を開く。Node.js 24 は Tonarium の開発サーバー用で、llama.cpp 自体は同梱の実行ファイルで動く。

初回だけ、公式ファイルの準備とモデルの起動を行う。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local-npc.ps1 -Prepare
```

すでに準備済みなら、ダウンロードせず起動できる。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local-npc.ps1
```

スクリプトはモデルと実行ファイルの SHA256 を確認し、`127.0.0.1:18081` にサーバーを起動する。バックグラウンドで動き、追加のコンソールウィンドウは開かない。モデルの API 名は `qwen3-1.7b`。起動完了時に PID と URL を表示する。同じスクリプトで起動したモデルがすでにある場合は重複起動を拒否する。

既定の起動条件は CPU 6 スレッド、単一モデルの生成スロット 2、各スロットのコンテキスト 4096（合計 8192）。モデルを 2 個読み込む構成ではない。K/V キャッシュは `q8_0`、Flash Attention を有効にし、重みは公式の Q8_0 を維持する。Jinja のチャットテンプレートと `--reasoning off` を使う。生成上限は通常の短い雑談 128、情報質問 160、詳しい説明を求めた場合 256 トークン。Web UI は起動せず、外部のネットワークインターフェースには公開しない。

Tonarium サーバーの `.env` は次の値を使う。

```dotenv
NPC_LLM_URL=http://127.0.0.1:18081/v1
NPC_LLM_MODEL=qwen3-1.7b
```

通常の開発サーバーを起動する。

```bash
npm run dev
```

ほかの作業と同時に動かす場合は、Tonarium の `SERVER_PORT`、`CLIENT_PORT`、`LIVEKIT_ROOM_PREFIX` を分ける。モデル用のポートも変更する場合は、起動時の `-Port` と `NPC_LLM_URL` を揃える。このスクリプトから既存の `.env`、セッション設定、PATH、レジストリ、Windows サービスは変更しない。

モデルだけを停止する場合は次を使う。記録した PID の実行ファイルが、この作業用 llama.cpp と一致するときだけ停止する。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local-npc.ps1 -Stop
```

PC の再起動後はモデルを再び起動する。自動起動サービスの登録は行わない。

## ファイルと容量

モデルや実行ファイルは `work/local-ai/` に置く。アプリの Web 配信データや、プレイヤーへ配る地図・画像のダウンロード容量ではない。

| --- | ---: | --- |
| `llama-b11856-bin-win-cpu-x64.zip` | 24,173,159 bytes | `b0be608ec81c811029406430796dfcd16b8d83dc152705a6682f0d47834a2f3b` |
| `llama-b11856/llama-server.exe` | ZIP から展開 | `1f34b3e7b8b9b77c2fbfbe90d2c70110d9118d8f08c852e8214ee1410ab4d027` |

ランタイムの展開先全体は約 59.4MiB。モデルの比較に使った旧 0.6B ファイルが残っている場合、その容量は別に約 610MiB ある。旧モデルは 1.7B の実行には使わない。モデルファイルとランタイムをソース管理へ追加する必要はない。

`server.pid` は停止用の PID、`server.stdout.log` と `server.stderr.log` はランタイムの起動診断。モデルの動作確認には、会話内容を調べずに次のヘルスチェックを使える。

```powershell
Invoke-RestMethod http://127.0.0.1:18081/health
Invoke-RestMethod http://127.0.0.1:18081/v1/models
```

起動中の初期化では `503 Loading model`、準備完了後は `status: ok` を返す。複数のモデルを同時に読み込むと RAM が不足し、初期化や応答が大きく遅れることがある。この環境では 1.7B を単独で実行する。

## 会話記録と限界

自由な雑談では、選択言語の短い人物設定と日常会話の指示を使う。韓国語・日本語でも性格と話し方をその言語で渡し、難しい比喩・詩・独り言や相手の言葉の反復を避ける。話者を取り違えない短い会話例を添え、相手の感情を自分の感情や過去に置き換えないよう指示する。質問そのものを定型の答えに置き換える変更ではない。情報の権限とゲーム行動の確認は従来どおりサーバーが管理する。GM の客観的な案内口調は変更しない。

NPC の自由生成の temperature はサーバー・本人のブラウザ・支援するブラウザとも 0.35。ブラウザの worker は要求された値を生成 API に渡し、常に 0.7 に上書きしない。これは生成の揺れを抑える設定で、文法・意味の正しさを保証するフィルターではない。

`npm run check:fantasy-npc-samples` は Docker の隔離された CPU モデルを起動し、実際の `NpcChat` 経路でオラン・リン・ボリン各三言語の合成会話を生成する。既存の接続確認に加え、`NPC_SAMPLE` 行に質問・返答・モデル・生成設定を残す。自動検査は接続・生成経路・モデル名・後片付けを確認し、文法と意味は人が読む。CI も同じ九件を採取する。比較実験では元の韓国語質問で英語の下書きを三件生成し（`NPC_PIVOT_DRAFT_SAMPLE`）、その下書きを韓国語へ訳す（`NPC_TRANSLATION_SAMPLE`）。これは本番の二段階生成ではなく、九件の実際の会話と区別する。実プレイヤーの記録は使わない。CPU の Q8 とブラウザの Q4 は別の実装・量子化なので、CPU の返答が自然でもブラウザの品質を検証したことにはしない。

会話の短い履歴は Tonarium サーバーのメモリ上で、仮ユーザー ID・NPC・言語ごとに分ける。それぞれ最近の最大 12 メッセージを保持し、文字数上限に合わせて古い往復を省く。NPC や言語を切り替えても、別の相手や言語の記録を混ぜない。元の言語に戻れば、その言語の履歴で続けられる。ウィンドウの最小化・閉じるでは画面の履歴と関係をリセットしない。ページ更新後の表示履歴や、アプリサーバー再起動後の永続的な記憶、プレイヤー間で共有する NPC の記憶はまだない。

相手との関係はサーバーが対話回数をもとに管理する。条件付きの事実は、関係とゲーム側で確認できる依頼達成などの条件を満たした場合だけ許可する。ユーザーが会話で条件を満たしたと主張するだけでは公開しない。管理用の非公開情報はモデルのプロンプトとクライアントから除外する。モデルへ渡すのは、その NPC に許可した情報と必要な公式用語だけ。

名前・年齢・性別・職業などの公開プロフィールや、専門範囲内の登録済み用語には設定データから答えられる。専門外の話題や未登録の固有語は、知っているふりをして意味や歴史を作らない。自由な雑談はローカルモデルへ送る。この分担と世界の正式な名前は [世界観設定集](world-bible.md) を参照。世界設定集そのものは開発用文書で、ゲームの図書館には並べない。ゲーム内の本は館ごとに所蔵を分けた 34 冊。

現地の図書館では、明示した読書依頼を生成モデルへ送らずに処理する。「시작하는 마나 를 읽고싶어」は所蔵本『숨에서 시작하는 마나』へ解決し、正式題名、空白の違い、館内で一致する部分題名にも対応する。英語の「I want to read Mana Begins with Breath」、日本語の「息から始まるマナを読みたい」も同じ扱い。複数候補は名前か番号で選び、その後の別の承認で開始する。内容や効果の質問、仮定、拒否を読書の承認に読み替えない。未所蔵・不明の題名は司書が案内するだけで、他館の本を読む権限を与えない。独立した確認画面や遠隔地からは読書を開始できない。既存の費用・時間確認（現在は 0G・世界時計の1時間）、活動中の制限、完了後の読了記録はゲーム側で引き続き検証する。

1 回の入力は最大 800 文字。公開設定や学習の提案など、ルールで答えられる質問は生成中かどうかの判定より先に処理する。画面も AI の返答準備中に対応する簡単な質問を送れるため、長い雑談の返事を待ってから全操作を再開する必要はない。要求ごとに送信したユーザー・NPC・言語を追跡し、返答が前後しても別の相手の履歴へ混ぜない。

ローカル AI が必要な要求は `server/local-inference.ts` の共通待ち行列を使う。NPC と GM を合わせて **生成は最大 2 件、待機は最大 4 件**。さらにサービスごとに生成の同時受付数と同ユーザーの重複、1.5 秒未満の連続生成を制限する。待ち行列がいっぱいなら HTTP 429 をサービスの混雑表示へ変換する。45 秒の制限には待ち時間も含み、中止された待機要求は列から取り除く。ブラウザ側は通信の余裕を含めて 55 秒で待機を解除する。モデルが停止している場合や処理が詰まっている場合は、その状態を返す。

雑談・気持ち・挨拶の文脈は本人と現在地、進行中の活動を優先し、関係のない所持品・依頼・設定を余った枠へ詰め込まない。GM の知識と短い履歴の予算は通常の雑談 550、情報質問 1400、詳細要求 1600 の保守的な推定トークン。NPC も許可された情報の中から質問に関係する事実を選ぶ。情報は行単位で選び、文を途中で切らない。公開権限を緩めて短縮する方式ではない。

判定世界のNPCとGMは、画面の進捗コールバックがあるとき `stream: true` と `cache_prompt: true` を送り、SSEの発話部分を生成途中から本人へ届ける。通常JSON応答との互換は維持する。ブラウザ1.7Bも同じく生成中の文字をワーカーから送る。貸出ID・接続・世代・同意・順番を確認し、推論文や期限切れの断片は表示しない。失敗した部分文は履歴に確定せず、サーバーへ切り替わると表示を更新する。共通生成枠は本文完了・中止まで占有し、DONE・中断・エラーでも解放する。これは最初の表示を早める仕組みであり、生成完了の速度向上を測定した結果ではない。

小さなモデルなので、言葉遣い、設定の整合性、長い会話の記憶には限界がある。2026-10-25 に同じ CPU・1.7B モデルで短い応答を測定した結果は次のとおり。生成したのは 47 トークンの 1 応答で、全質問の速度を表すものではない。

| 測定対象 | 実測値 |
| --- | ---: |
| 応答完了までの実時間 | 3.24 秒 |
| 処理中に増えた CPU 時間 | 12.38 CPU 秒 |
| 上記から求めた平均使用コア数 | 約 3.8 コア |
| 観測したプロセスの最大ワーキングセット | 2,532 MiB |
| 使用モデルのディスク上の大きさ | 1,834,426,016 bytes |

以前の GM 経路では 12〜17 秒の応答も測定している。短い直接応答と、知識・履歴を含む GM の要求は条件が異なるため、これを速度改善率の比較には使わない。応答長、入力の長さ、待ち行列、PC の併用状況でも変わる。ワーキングセットはその測定で観測した値であり、アプリ全体の RAM 使用量や最低必要メモリではない。

同じ中立質問・temperature 0・seed 2026 を使った CPU 比較では、4 スレッドの単独応答 4.580 秒／2 応答完了 6.080 秒、6 スレッドは 4.467 秒／5.307 秒、8 スレッドは 4.407 秒／5.364 秒だった。4 スレッドは 1 回、6 と 8 は各 2 回の測定で、少数試行の差を一般化しない。2 件時の結果と CPU の余裕から既定値は 6 を採用した。詳細は `work/local-ai/cpu-tuning-results.json`。モデルの重みや量子化を小さなモデルへ変更した比較ではない。

文脈選択と短い出力の適用後に、初めての旅への緊張を相談する中立質問を各言語・各サービスで 1 回ずつ実測した。CPU 6・2 スロット・Q8 K/V、履歴なしの合成人物（人間・無職・ハース・35G・活動なし）を使い、要求は 1 件ずつ送った。

| サービス・言語 | 応答完了 | 実際の入力 / 出力トークン |
| --- | ---: | ---: |
| GM・韓国語 | 3.527 秒 | 261 / 21 |
| GM・英語 | 3.759 秒 | 235 / 33 |
| GM・日本語 | 3.707 秒 | 265 / 27 |
| NPC リン・韓国語 | 4.582 秒 | 213 / 51 |
| NPC リン・英語 | 4.088 秒 | 200 / 45 |
| NPC リン・日本語 | 3.417 秒 | 216 / 38 |

元の GM で同じ質問を使った 18.609／21.132／19.414 秒の測定とは、CPU と履歴が異なる。純粋なコード変更だけの改善率とは言えない。新測定の入力処理は約 1.475〜2.444 秒、生成は約 1.049〜2.626 秒。原文の質問・回答とモデル報告値は `work/local-ai/prompt-context-optimized.json` に記録する。返答は各言語で返ったが、曖昧な励まし、根拠のない「準備できている」という表現、2 文の指定を超える例も残った。速度の測定は設定忠実性や助言の品質の保証ではない。

0.6B より会話は改善したが、韓国語・日本語の不自然な表現、質問の一部の見落とし、未登録の歴史を作る問題が実際にあった。そのため公開情報の制限と設定参照の応答を追加する。自然な会話が返ることと、ゲーム設定への完全な忠実さは別。NPC の発言だけで、ゲーム世界の事実や依頼達成を確定させない。

対応する NPC は、現地の建物と教えられる職業に合う場合に職業取得ボタンを提案できる。押した後の取得はゲームエンジンが検証し、ゲーム内 1 時間、実時間 2 分の学習を終えて確定する。モデルの文章だけで職業を変更しない。新規キャラクターは無職で始まる。

技を教える NPC には、別に学習ボタンがある。基礎の受け流し・落ち着いた手仕事・基礎の集中の 3 技は、1 技 5G・ゲーム内 1 時間。所在地・設備・専門・資金・重複をエンジンが検証し、完了して初めて料金を払い技を習得する。転職しても学んだ技は残る。無職や戦士系を含め職業に関係なく取り組めるマナ修練もあり、段階 0〜4 と負荷を保存する。詳細は [RPG のマナ・学習規則](fantasy.md#マナ修練と師からの学習) を参照。

現地 NPC への共同準備は、生活・設備・研究・住人の支援への協力を共有記録に残す仕組み。3 回ごとに 2 人の NPC が協力した通知を作り、条件を満たす現在地の事実として会話へ渡す。自由生成された会話から実際の共同活動や報酬を作る機能ではない。

RPG はサーバー共通の世界時計を使い、実時間 1 分 = ゲーム内 30 分に固定する。進行中の活動があっても会話できるが、会話によって期限を飛ばしたり活動を早く完了したりはできない。時刻・活動の保存とオフラインの食品・空腹の扱いは [RPG の時間規則](fantasy.md) を参照。

## GM のローカル会話

GM も同じ運営側モデルを使う。仕事・移動・依頼などの既知ルールは登録データから返し、それ以外の自然な質問をローカル AI へ送る。生成中でもルール質問は先に返せる。渡すのは現在の人物に許可した記録だけで、未知の地名、他種族の限定依頼、未鑑定の食品の正確な状態、NPC の秘密は除く。本人のマナ段階・負荷、装備、継続中の状態、師から学んだ技もその範囲に含める。

GM の会話履歴は NPC と分ける。生成用の短い文脈は仮ユーザー ID・言語ごとのサーバーメモリに置き、画面の履歴はメニューを移っても維持する。要求ごとに送信時のユーザーと言語を記録し、後から届いた応答も元の会話へ戻す。永続保存ではなく、ページ更新とサーバー再起動を越えた長期記憶にはしない。GM のゲーム行動は提案内容・料金・時間を確認してから開始し、キャンセルもできる。ユーザーや記録の版が変わった提案は再確認が必要。文章だけで行動や職業取得を確定しない。

音声会話、音声合成、自律的な NPC 社会シミュレーション、永続的な長期記憶、ローカルモデルによる直接のゲーム操作、公開運営サーバーへの配備はこのプロトタイプの範囲に含めていない。

## NPC의 인물 대화와 시설 지식

NPC는 세계 안에 사는 인물로 말한다. 고정 응답에서 게임·공식 설정집·버튼 등을 안내하던 표현을 없앴고, 브라우저와 중앙 모델의 생성 결과에도 같은 말투 검사를 적용한다. 개발 환경·AI·화면 조작을 설명하는 대사는 전달하지 않고 인물이 직접 아는 일만 이야기하는 짧은 대사로 바꾼다. 평범한 도서관의 책·기록과 음식점의 메뉴는 정상적인 세계 안의 표현으로 허용한다.

객실·식사·판매 재고·가격·도서관별 소장 도서·가르칠 직업과 기술·작업장 제작품·어선 대여와 구매는 현재 게임 데이터에서 조회해 한국어·영어·일본어로 답한다. 객실은 공동 객실·개인 객실·특실이며 트리플·펜션·특별 할인 객실은 만들지 않는다. 가격은 시설 화면과 같은 흥정 적용 함수를 사용하고, 객실 회복 차이는 편히 쉬는 정도로 설명한다. 길드 의뢰는 서버가 전달한 현재 지역의 게시물 중 미선점·미만료·수락 조건을 만족한 것만 안내한다. 안내 대사 자체는 구매·수련·의뢰 수락이나 보상을 실행하지 않는다.

예전 대화에 잘못된 객실이나 개발 환경 설명이 있어도 다음 생성의 사실로 재사용하지 않는다. 시설 관련 대화 기록 대신 최신 시설 지식을 우선 넣고, 일반 잡담 기록만 짧게 이어간다. 시설 전체 재고를 검색하는 다국어 검사와 브라우저·중앙 생성의 말투 검사, 과거 잘못된 대화 기록의 제외는 `server/npc-facility.test.ts`에서 검증한다.

NPC 대화창은 데스크톱에서 제목 표시줄을 마우스로 끌어 옮긴다. 최소화·다시 열기·다른 NPC로 변경할 때에도 같은 플레이어와 월드 안에서는 위치를 기억하고, 화면 크기가 바뀌면 가장자리 안으로 조정한다. 모바일은 기존 전체화면 배치를 유지한다. 등록된 인물은 137명이다. 137명 모두 [개별 상반신 일러스트](npc-portraits.md)를 사용하며 신규43명의 얼굴·손·복식·기후 표현도 제작·검수했다.

이번 검증은 판타지 446개·NPC 48개·클라이언트 30개·브라우저 지원 38개로 총 562개 테스트와 타입 검사·웹 빌드가 통과했다. 실제 배포 빌드에서도 첨부 사례의 두 질문과 식사 안내를 확인했고, 대화창 좌표가 (376,24)에서 (176,34)로 이동한 뒤 최소화·재열기에도 유지됐다. 검증용 저장 데이터는 `work/qa/npc-dialogue-data/`로 실제 플레이 데이터와 분리했다.

## 세 대륙의 새 정착지 주민

노크티스·실바라·카자란에 각각 도시 한 곳과 마을 두 곳을 더하고, 33개 신규 시설에 서로 다른 담당자를 배치했다. 아홉 지역의 생활 주민과 햇살목초지 여관의 페이까지 신규 43명이다. 이름·나이·성별·종족·전문 분야·성격·말투를 한국어·영어·일본어로 정했으며, 기존 주민의 위치나 역할은 바꾸지 않았다. 20개 도시·마을·항구에는 여관과 여관 주인이 있으며 연구탑·야외·무인섬에는 여관을 일괄 추가하지 않는다.

새 직원도 객실·식사·판매 재고·도서관 서가·수업을 기존의 실제 시설 자료에서 조회한다. 흥정은 해당 시설의 서비스만 대상으로 하고 별도의 말로 승인한 뒤 적용한다. 솔바람마을의 털 방한복, 실바라의 통풍 저고리와 비막이, 카자란의 가벼운 아마포와 밤 덧옷을 문화·기후 정보에 반영했다. 의복과 지역의 공개 관습은 대화할 수 있지만 개인적인 속내와 신뢰 조건이 붙은 이야기는 공개 지식에 합치지 않는다.

## 도서관의 독서 요청과 응답 지연

도서관 NPC에게 명시적으로 읽기를 요청하면 생성 모델을 호출하지 않고 규칙으로 응답한다. 한국어·영어·일본어의 읽기 의사와 제목의 띄어쓰기·문장 부호를 정리하고, 해당 서가의 정확한 제목 또는 유일한 부분 제목을 실제 책 ID로 연결한다. 예를 들어 하스의 미라에게 “시작하는 마나 를 읽고싶어”라고 하면 “숨에서 시작하는 마나”의 정독을 제안한다. 책의 내용·효과를 묻거나 읽지 않겠다고 한 대화는 독서 요청으로 바꾸지 않는다.

제안만으로는 상태를 바꾸지 않는다. 여러 권이면 먼저 제목이나 번호를 고르고, 이후 “응”, “yes”, “はい”처럼 따로 승인해야 기존 독서 활동이 시작된다. 현지 소장·위치·삶·기록 버전·완독 여부·진행 중인 활동과 비용·시간은 기존 서버 규칙으로 검증한다. 없는 책·다른 도서관의 책·이미 정독한 책은 인물의 말투로 안내하며 행동을 만들지 않는다. 다른 자유 대화가 준비 중이어도 도서관 NPC의 명시적 독서 요청은 보낼 수 있다.

2026-10-25 지연 조사에서 부분 제목을 인식하지 못해 불필요한 로컬 생성으로 넘어가는 경로를 재현했다. 당시 모델은 CPU6스레드·Qwen3-1.7B Q8_0·동시2건이었고, 확인 시점16GB 메모리 중 여유는 약0.8GB였다. 실행 로그에는 생성 시작 후 약45.236초에 취소된 작업이 있었다. 로그에 대화 요청 ID가 없어 그 작업을 특정 사용자 문장과 확정 연결하지는 않는다. 큐가 단일 직렬이거나 입력이 최대 문맥을 초과한 것으로 확인된 사례는 아니다. 독서 요청의 불필요한 생성 호출을 없앴으며, 이후 후속 확장에서 자유 답변의 중간 문장 표시도 추가했다. CPU·메모리 상태에 따른 실제 생성 시간은 별도 영향을 받는다.

## NPC별 말투와 GM 안내체

NPC137명의 등록된 성격·말버릇과 직종, 낯선 사이·안면·신뢰 관계를 대화 지시에 함께 넣는다. 여관 주인의 친근한 접객, 상인의 간결한 거래, 대장장이의 짧고 투박한 말, 학자의 정확한 표현, 사제의 절제된 배려, 지도자의 결단, 뒷세계 인물의 경계를 구분한다. 인사는 생성 모델 없이도 인물의 역할과 관계에 맞춰 다르게 답한다. 짧은 일상 대화는 규칙으로 응답하고 복합적인 질문은 기존의 사실 조회·자유 대화 경로를 유지한다.

GM은 한국어·영어·일본어 모두 감정적 맞장구를 줄인 간결하고 객관적인 안내체를 쓴다. 일반 인사는 짧게 문의를 받고, 상태 질문은 현재 기록을 기준으로 답한다. 생성 결과에 붙은 추천 질문과 불필요한 되묻기는 최종 대화와 다음 대화의 기억에서 제외한다. 직접 브라우저·운영 서버·다른 참여자의 공유 지원 경로에 같은 말투 지시를 적용한다. 공유 지원에는 사적인 관계 기록을 넘기지 않고 공개 인물 정보와 낯선 방문자 기준만 사용한다. 작은 모델의 모든 자유 발화가 항상 자연스럽거나 완전히 동일한 말투를 지킨다는 보장은 하지 않는다.

## 자주 묻는 일반 질문의 사전 대사

버전5에서는 NPC가 정확한 기온을 말하지 않고 영하의 추위·추움·쌀쌀함·온화함·더위·무더위의 체감으로 설명한다. 실제 기온과 날씨는 세계 환경 계산에 그대로 사용하고 NPC에게 전달하는 자유 생성 자료도 체감 표현으로 바꾼다. GM의 수치 안내는 유지한다.

시설 소개와 관계 답변은 단순 어미 교체가 아니라 여관 주인의 배려, 상인의 조건 확인, 장인의 실용성, 학자의 근거, 사제의 돌봄, 지휘관의 판단, 범죄 조직 인물의 경계, 주민의 생활 감각으로 구분한다. 시설 안내를 모두 ‘물어보세요’로 끝내지 않는다. 일반 대화 일곱 주제에 성향별 기본 문장168개를 추가하고 안부에는 각 인물에게 이미 정해진 공개 취미를 반영한다. `npc-persona-lines.ts`가 이 응답을 제공하고, 관계 단계는 `npcRelationshipSpeech`가 실제 대화 기록에 맞춰 선택한다. 새로운 과거 사건·특혜·친분을 만들어 붙이지 않는다.

`shared/fantasy-npc-query.ts`와 시설 질문 분류는 질문 전체가 준비된 응답의 범위에 드는지 확인한다. 신원 단어가 들어 있거나 지역명이 언급됐다는 이유로 일부 안내만 내놓지 않는다. 상세 질문·복합 질문·개인적 추천과 이유를 묻는 질문은 실제 NPC 설정과 허용된 현재 정보로 실시간 AI 생성에 연결한다. ‘요리사가 되고 싶어. 가르쳐줘’처럼 같은 수련 요청의 반복은 하나의 의도로 유지한다. 존재하지 않는 이름·미확인 가격·비공개 전직 조건에 관한 기존 지식 제한과 행동 승인 절차는 유지한다. 실시간 생성 연결은 합성 전송 응답으로 검증하며 이번 검사에서 실제 로컬 모델을 띄우지는 않는다.

버전5 검증은 NPC145건·RPG905건·브라우저 AI92건·클라이언트47건, 총1,189건과 타입 검사·빌드를 통과했다. 세 언어와 다섯 NPC에 걸친60개 자유 질문 조합이 전체 입력·정확한 인물 설정을 포함해 생성 경로로 전달되는지 확인했다. 이60개는 합성 HTTP 응답을 사용하는 경로 검증이며 실제 Qwen의 답변 품질 표본은 아니다. [522개 서비스 응답 예시](../work/qa/dialogue-templates-preview.html), [이전 문장과 비교](../work/qa/npc-distinct-before-after.json), [최신 검증 보고서](../work/qa/npc-distinct-complete.json)를 제공한다. 전체137명·세 언어·열네 주제의 실제 조합 결과5,754개와 성향 문장168개는 [대사 자료](../work/qa/dialogue-templates-catalog.json)에 보관한다.

버전4는 NPC 정보 안내도 대화체로 통일한다. 가격·재고는 ‘회복 약초는 하나에4G예요. 지금14개 있어요.’처럼 말하고, 날씨·소식·행동·의뢰·숙박·식사·도서·수업·제작·배 안내도 완성된 문장으로 표현한다. 여러 가격 묶음은 각 묶음의 가격과 수량을 그대로 설명한다. 한국어의 친근한 말투·장인과 지휘관의 말투·정중한 말투, 일본어의 경어와 보통체, 영어의 직종별 표현을 나눈다. GM의 객관적 안내체는 유지한다.

용어집의 ‘이름: 설명’과 성격·말버릇 지침을 그대로 읽지 않고, 확인된 공개 설정을 NPC 자신의 말로 설명한다. 부대·소환 계약·마법 합성·연금술, 공동 준비·옛 여행자 기록, 항해 단서, 비용을 포함한 행동 확인에도 같은 원칙을 적용한다. 자유 생성 입력에는 표·항목·콜론·곱셈 기호를 낭독하지 말라는 지침을 추가하고, 서버에서 전달하는 수치 자료 자체는 간결한 기존 형식을 유지한다. 현재 값·허용 지식·승인 여부·캐시 범위는 바꾸지 않는다. 검수용 소문의 허구 여부는 자료의 별도 설명에 두며 NPC의 말에 ‘합성 검증 공지’라는 출처 표식을 넣지 않는다.

버전4는 NPC134건·RPG905건·브라우저 AI92건·클라이언트47건, 총1,178건의 회귀 검사와 항해 단서8건 재검증을 통과했다. 330개 서비스 응답 예시와 문장 변경 비교에서 현재 정보 갱신, 모델 호출·행동 제안·프로필 변경0건을 확인했다. 전체137명의 정보 표현·51종족 설명·64가지 고유 성격을 세 언어로 검사했다. [최신 검증 보고서](../work/qa/npc-information-complete.json)와 [이전 문장 비교](../work/qa/npc-information-before-after.json)에 기록한다. 직접 브라우저 클릭 검수나 로컬 모델을 띄운 자유 생성 품질 검수는 이번 변경에서 하지 않았다.

현재 버전3은 기존 열두 유형에 사과·칭찬을 더한 열네 유형, 총756개 문안과 모르는 정보에 대한54개 문안을 갖는다. 이 부분은 개발 중 Codex AI로 작성하고 검수한 콘텐츠다. 기존 규칙 응답 전체를 AI로 미리 생성했다는 뜻은 아니다. 신원·시설·거래·행동 판정 같은 기존 안내에는 코드로 직접 작성한 문장도 있다.

`server/dialogue-knowledge.ts`는 짧은 낱말·이름 설명 요청을 확인하고, 확인되지 않은 이름이나 플레이어가 아직 모르는 지역은 추측으로 설명하지 않는다. NPC는 자신의 말투로 모른다고 답하며, GM은 객관적인 확인 불가 안내를 쓴다. 이전에 잘못 말했다는 기록이 없을 때 임의로 사과 이력을 만들지 않는다. 복합 질문·조언·철학적인 대화·행동 요청은 이 분류가 가로채지 않는다. 등록되지 않은 복잡한 자유 발화 전체의 설정 오류를 보장하는 필터는 아니다.

`shared/fantasy-npc-preferences.ts`에 등록된137명 각각의 좋아하는 실제 음식, 취미, 싫어하는 것을 고정된 공개 설정으로 둔다. 한국어·영어·일본어 응답과 자유 생성에 같은 설정을 사용한다. 취향이 선물 보너스나 관계 변화 규칙을 추가하지는 않는다.

가격·오늘의 소식·날씨·진행도는 `server/dialogue-dynamic.ts`의 문장 틀에 요청 시점의 서버 값을 넣는다. 물건은 실제 거래소의 묶음별 가격·수량, 객실·식사는 현재 흥정과 평판, 소식은 세계 시각의 같은 날짜에 해당 지역에서 확인된 공공 기록, 날씨는 현재 지역·세계 시각을 사용한다. 진행도는 본인의 현재 행동과 받은 의뢰만 쓰며 NPC는 자신이 맡긴 의뢰만 안내한다. 결과 문장이나 개인 상태는 공용 캐시에 넣지 않고, 원래 구매·이동·수련 승인 절차도 유지한다. NPC에게는 세계 안의 시간으로 말하며 GM은 현실 시간도 함께 안내한다. 거래 정보가 없으면 가격을 추정하지 않는다.

버전3 검증은 NPC125건·RPG905건·클라이언트47건·브라우저 AI92건, 총1,169건과 타입 검사·빌드를 통과했다. 합성 인물과 현재 정보 스냅샷을 실제 서비스에 넣은204개 응답에서 모델 호출·행동 제안·프로필 변경은 모두0이었다. 직접 브라우저 클릭 검수는 수행하지 않았다. [응답 예시](../work/qa/dialogue-templates-preview.txt), [전체 문안과 취향](../work/qa/dialogue-templates-catalog.json), [최종 검증](../work/qa/dialogue-templates-complete.json)에 상세 기록을 둔다. 원본 저장 데이터와 이전 빌드 자산을 보존했으며 테스트용 임시 서버 외에 게임·모델 서버는 시작하지 않았다.

이하 버전2의 교열 기록은 이전 단계의 검증 결과다.

인사·작별·감사·안부·일반적인 피로·걱정·외로움·응원·가치관·여행 준비·도둑질에 대한 입장·간단한 마나 정의의 열두 유형은 AI가 사전에 작성하고 검수한 고정 대사를 사용한다. NPC용은 여덟 말투와 세 언어별로 두 문안, GM도 세 언어별로 두 문안을 갖는다. 등록된137명 모두 이 대사집을 사용하며, 직종·성격·말버릇과 관계를 바탕으로 문안을 선택한다. 각 인물에게 완전히 다른 원문 전체를 생성했다는 뜻은 아니다. GM은 개인적인 감정이나 플레이어의 마음을 추측하지 않는 객관적인 안내체를 쓴다.

이 문안은 Codex AI가 개발 중에 작성한 콘텐츠이며, 요청 때마다 로컬 Qwen이 생성한 결과로 표시하지 않는다. NPC는 기존 확정 안내인 `canon`, GM은 `rules`로 전달한다. 준비된 질문에는 브라우저·공유 기기·운영 서버 모델의 생성 호출과 대기열이 필요 없다. 같은 인물·언어·관계·주제와 첫 인사 여부에는 같은 문안을 사용하고 다른 질문의 대화 기록으로 섞지 않는다.

대사집 버전2에서는 세 언어648개 문안을 모두 교열했다. 첫 만남은 짧은 인사와 이름 소개를 합쳐 두 문장 이내로 만들고, 한국어 이름의 받침과 말투에 맞춰 조사·어미를 고른다. 성공한 대화가 이미 있는 NPC에게 재인사하면 소개를 반복하지 않는다. 이 여부는 서버의 해당 대화 기록으로 결정하며, 관계 등급이나 지식 권한을 올리지 않는다. 친숙하다는 이유로 모든 문장 앞에 ‘친구야’ 같은 호칭을 붙이지 않고, 기존 짧은 안부 문형도 같은 교열 대사집을 사용한다.

안부는 성격 소개 대신 안부에 직접 답하고, 감사·작별·응원은 불필요한 훈계나 추상적인 비유를 줄였다. 마나 정의의 두 문안 모두 마법과 신체 강화에 쓰는 힘이라는 설명을 포함한다. 기본 신원·나이·성별·직업 답변은 직접적인 자기소개로 바꾸고, 수업·시설 안내의 한국어 조사와 정중체, 영어 관사도 함께 다듬었다. 비용·수련 조건·판매 목록·행동 승인과 개인 기록은 바꾸지 않는다. 이미 표시된 과거 대화는 고쳐 쓰거나 지우지 않고 새 응답부터 적용한다.

질문 전체가 등록된 짧은 문형일 때만 사전 대사를 사용한다. 단어 하나가 포함됐다는 이유로 매칭하지 않으며, 복합 질문·가격·재고·시간·현재 능력·현재 행동·개인 기록·행동 요청·전직 조건·미발견 설정은 기존의 현재 정보 조회와 승인 경로를 따른다. 따라서 ‘마나가 뭐야?’는 준비된 정의를 쓰고 ‘내 마나가 얼마나 남았어?’는 현재 상태를 조회한다. ‘남의 물건을 훔쳐도 괜찮을까?’는 윤리와 위험에 대한 대사를 쓰며 상품 목록으로 분류하지 않는다. 등록되지 않은 표현과 상세 질문은 기존 자유 대화로 이어진다.

자료는 `shared/fantasy-dialogue-prewritten-text.ts`, `server/fantasy-gm-prewritten-text.ts`에 보관하고, 인식 문형은 `shared/fantasy-dialogue-topics.ts`, 서버 선택·캐시는 `server/dialogue-prewritten.ts`에서 관리한다. 가격·재고·현재 수치와 퀘스트 결과를 고정 대사에 저장하지 않으므로 오래된 거래 조건이나 미확인 행동 결과를 재사용하지 않는다.
