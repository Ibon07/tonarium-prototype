# 実装の構成と設計

ディレクトリの構成は README.md。


## 設計上のポイント
- LiveKit 接続は `client/src/net/livekit.ts` に1つだけあり、2D/3D の表示コンポーネントとは無関係に生きている → 表示切替で通話・配信が切れない
- セッション内の位置・アイテム・チャット・参加者の状態は kokosync、誰がどこにいるか・フレンド・ホーム・受信箱は既存の WebSocket で流す。`client/src/net/session.ts` が接続、初回同期、再接続を担当し、LiveKit の通話接続と独立して動く。最大5人への直結を試し、接続できなければkokosyncで中継する。`shared/session-events.ts` は全体チャット・キャンバス差分・サイコロ更新の暗号化した本文を先にP2P配送し、サーバーの権限判定・順序確定後に適用する。初回同期・旧クライアント・P2P欠落時の補完はサーバーが担当。詳しくは [sync.md](sync.md)
- 配信映像は1つの `<video>` を 2D のウィンドウと 3D の配信ディスプレイ（VideoTexture）で共有 → 二重再生しない。音声は表示と無関係に1回だけ attach
- 2D の画面は「背面にウィンドウ、前面に半透明のパネル」。3D のときは背面が 3D 空間になり、前面のパネルはそのまま残る
