# ホーム（セッション外の画面）

名前を入れて「はじめる」の後、セッションに入っていないときに出る画面。部品は `client/src/home/`。

## 画面

セッション中にグローバルメニューから開くシートは表示領域内に固定し、上部の検索・通知・作成ボタンとナビゲーションを残して本文だけをスクロールする。変更履歴の末尾や、ホーム・フレンド・セッション・イベント・グループ・ワールド・アイテム・マーケット・リアクション一覧の長い内容も、この本文領域で閲覧できる。ページを切り替えると本文のスクロール位置は先頭に戻る。変更履歴の「開発・保守を含める」は本文上端に残る。ナビと右の補助欄も個別にスクロールでき、端まで進んでも親や背面へスクロールを伝播させない。幅 721〜1100px では右の補助欄を本文の下に分け、スマホ表示では従来どおり下部ナビを使って補助欄を隠す。

- **左のナビ** ページとリンクはホーム／タイムライン（[timeline.md](timeline.md)）／フレンド／セッション／イベント／グループ／ワールド／アイテム／マーケット／変更履歴／フィードバックの順（最後に開いたページをブラウザに覚える）。フレンドには未読の DM があればその数（赤）、なければオンラインのフレンドの人数、イベントには 1 週間以内のイベントの数が出る。マーケットの下に所属グループの頭文字（押すとグループの画面。未読があれば赤い点）、クライアントモード（[screens.md](screens.md)）があり、その下の自分のカード（押すとステータス、歯車でプロフィール設定）の上に「変更履歴」「フィードバック」が並ぶ。「フィードバック」は Notion のフォームを新しいタブで開く（URL は `client/src/feedback.ts`。最初の画面の「このサイトについて」にも同じリンクがある）。セッション中のメニューから開いたときは「セッションから離脱」も出る
- **上** 検索（開いているページのセッション・フレンド・グループ・ワールド・アイテムを名前で絞る）、通知のベル（フォローされた通知と招待。未読があると赤い点）、「セッションを作る」
- **ホーム** 各セクションは 1 段だけで、はみ出す分は横にスクロールし、タイトルの横の「もっと見る」でそれぞれのページへ行く。上から「フレンドの今」（→ フレンドの「フレンドの今」タブ）・「オンラインのフレンド」（→ フレンド）・「直近のイベント」（→ イベント）・「パブリックセッション」（→ セッション）・「新着ワールド」（→ ワールド）。24 時間以内に「来る」と答えたイベント（開催中も含む）があるときだけ「直近のイベント」を一番上に出す。「フレンドの今」と「直近のイベント」は出すものが無ければセクションごと出さず、ほかは「〜はありません」と出す。「フレンドの今」はフレンドがいるセッションだけを、「参加 OK」のフレンドがいるものを先に、中にいるフレンドが多い順に並べる。「直近のイベント」は開催中（始まってから 3 時間。イベントは終わりの時刻を持たないため）を先に、次に 1 週間以内のものを近い順に。イベントのカードはセッションと同じ形で、主催・来る人・「来る／たぶん／むり」・会場があれば「会場へ」。「パブリックセッション」はフレンドがいないけれど入れるセッション（見えているセッションはどれも入れる）。「新着ワールド」のカードから、そのワールドでセッションを作れる。検索するとどのセクションも絞り込まれる。カードの下には、残っているアイテムのひとこと（盤面が途中など）と次のイベントが出る。カードには人数・画面共有中・ワールド・公開範囲・中にいる人（フレンドが先。名前の横に 2D/3D/画面共有のアイコン）が出て、「参加する」で入る。「オンラインのフレンド」には参加できるセッションにいないフレンドが並び、「誘う」でセッションかグループに誘える。右の欄はタイトルのドロップダウンで切り替える（ブラウザに保存。タイムラインのページでは書く欄・ポストの詳細で上書きする）：フレンドの今（フレンドがいるセッション。押すと参加）・イベント（今週のカレンダーと 1 週間以内のイベント）・参加できるセッション・ワールド・アイテム（セッション中は押すと目の前に出す）。グループの画面以外のどのページでも出る
- **フレンド** 「フレンドの今」はフレンドがいるセッションをホームと同じ順でカードに並べる。「すべて」は左にフレンド全員（オンラインが先。ステータスと未読の数）、右に選んだ相手との DM。相手のステータスに合わせて「参加する」か「行ってもいい？」が出る。「フォロワー」に自分をフォローしている人（「フォローバック」でフレンド）、「フォロー中」に自分がフォローしている人、「ブロック中」にブロックした人（解除）。フレンドはお互いにフォローしている人（[timeline.md](timeline.md#フォロー)）
- **セッション** 参加できるセッション全部。自分が作ったものは、だれもいなければ「消す」。ユーザーが作ったセッションは、だれもいなくなってから 5 分で自動的に消える（固定セッションと、開始済みのお絵描き伝言のアイテムがあるセッションは除く）。作成直後や再起動直後も同様。セッション中は上に「参加中」のセッションと、ワールドの切り替え・離脱
- **イベント** 日付ごとの一覧（「月」でカレンダー。日を押すとその日だけ）と「イベントを作る」。どのイベントにも主催者（作った人。自分なら「あなた」）が顔つきで出る（ホームの右の欄・グループの画面も同じ）。「来る／たぶん／むり」で返事（押し直すと取り消し）、会場があれば「会場へ」で入る。作った人は消せる
- **グループ** 所属しているグループとほかのグループ。「入る」「抜ける」「フレンドを誘う」。作った人は消せる。名前を押すとグループの画面（チャンネル・セッション・イベント・メンバー。[messages.md](messages.md)）
- **ワールド** ワールドの種類の一覧。「このワールドでセッションを作る」。セッション中は「このワールドに切り替える」
- 参加中のセッション一覧の「ワールドを切り替える」は、ページを移動せずワールド選択モーダルを開く。一覧と共通の検索・所有状況による絞り込みを使い、現在のワールドと切り替え待機中は選択できない。変更先を選ぶと既存の確認画面が開き、確定後に 3 秒のカウントダウンを経て全員のワールドが切り替わる。モーダルの「閉じる」・背景クリック・Esc、または確認画面のキャンセルでは変更しない。誰でも切り替えられる権限は従来どおり。
- **アイテム** 標準の 8 種（付箋・ピコピコハンマー・チェス・チェスAI・2048・キャンバス・カメラ・サイコロ）と、マーケットで購入した「おしゃべりカード」「ようこそのメッセージ」を挿絵付きのカードで表示する。画像・動画・YouTube は一覧に含めない。カードを押すとマーケットと共通の詳細画面が開き、名前・ジャンル・2D/3D 対応・説明・使い方・挿絵を確認できる。「一覧に戻る」で一覧へ戻る。3D 対応アイテムは、新しく置いたときの姿も表示する（サイコロはまだ振っていない空の器）。ドラッグで回転、ホイールで拡大し、「視点を戻す」で最初のカメラに戻せる。2048 は挿絵のみ。購入済み商品は文字入り付箋の 3D プレビューになる。セッション中は一覧と詳細の「目の前に出す」で配置できる。カメラは 3D モードでのみ配置できる
- **変更履歴** 主な機能追加・挙動変更を新しい順に表示する。[検索と未読の目印](#変更履歴)を参照。

## 変更履歴

左ナビの「フィードバック」のすぐ上にある「変更履歴」から開く。セッション中のハンバーガーメニューから開くシートでも同じページを使える。

日付・見出し・本文の箇条書きを新しい順に表示し、タグがあれば見出しの横に小さく表示する。上部の検索欄では見出しと本文の部分一致で絞り込める（大文字小文字は区別しない）。該当する項目がなければ「該当する変更履歴はありません」と表示する。

「開発・保守を含める」チェックボックスは初期状態ではオフで、タグが「開発・保守」の項目だけを除外する。他のタグやタグのない項目は表示対象になる。チェックを入れると開発・保守も表示し、外すと再び除外する。現在の選択状態はチェックの有無で確認できる。検索と併用すると両方の条件を満たす項目だけを表示し、検索欄を空にしてもチェック状態は維持する。Web・Electron 版で共通の操作。

まだ見ていない日付の項目があると、ナビに赤い点が出る。ページを開くと最新日付を `localStorage` の `tonarium.changelog.seen` に保存して点を消し、再読み込み後も既読を保つ。保存できない環境でもページは開けるが、再読み込みすると未読に戻る。

データは既存の `shared/changelog.ts` と作業別の `changelog/*.json` を Web のビルド時に自動集約する。修正・文書更新・保守を含む全タスクで、独立した JSON ファイルを追加する。記載方法・識別子・並び順・重複防止・完了チェックは [変更履歴の開発ガイド](changelog.md) を参照。同じ日付の項目を追加しても、その日付をすでに見た人には赤い点を出さない。

## セッションの公開範囲
「セッションを作る」で名前・トピック・ワールド・公開範囲を決める。作成すると作成者は自動でそのセッションに参加する（参加中のセッションがある場合は移動する）。見える人は `shared/home.ts` の `canSeeSession` で決め、サーバーは見えないセッションには入れない。
- **パブリック** だれでも
- **フレンド+** 作った人のフレンドと、中にいる人のフレンド（人の出入りで見える人が変わる）
- **グループ+** そのグループのメンバーと、メンバーのフレンド（中ではゲストとして表示）
- **グループ** そのグループのメンバー
- **インバイト** 作った人と、誘われた人だけ
作った人がだれかを誘うと、その人は `invited` に入って以後ずっと見える。`sessions.json` のセッションはパブリック扱い。

## グループ・イベント・招待
グループの歯車は owner（作成者）と編集者だけに表示される。設定から名前（前後の空白を除いて40文字まで）と端末の画像を変えられる。owner だけがメンバーから編集者を追加し、一覧の × で外せる。編集者管理は選択時に、名前は「名前を保存」で反映する。グループの削除も owner のみ。色の変更と画像の削除は扱わない。

`groupUpdate { groupId, name?, editors? }` をサーバーで検証し、名前は owner/編集者、編集者変更は owner のみ受け付ける。不正な要求は無視し、変更後は `groups` を全員へ再配信する。`editors` は名前の配列で、owner・非メンバー・重複は除く。脱退時にも編集者から外れる。名前そのものの認証は別 Issue の範囲。

画像はプロフィールアイコンと共通の処理で中央を正方形に切り抜き、128px JPEG に変換し、`POST /group-image/:groupId?name=<送信者名>` へ送る。サーバーも名前で owner/編集者を検証し、アイコンと同じ JPEG 判定・300,000 バイト上限を適用する（元ファイルの拡張子では判定しない）。`data/group-images/<groupId>.jpg` に保存し、異なる拡張子の旧画像は削除する。`imageVersion` を増やし、`GET /group-image/:groupId?v=<imageVersion>` で配信する。グループ削除時は画像も削除する。

見出し・所属グループのナビ・一覧・セッションの公開範囲のチップ・会話一覧は共通の `GroupAvatar` を使い、画像がなければ従来の頭文字を表示する。画像は選択後すぐに保存される。グループの名前・`editors`・`imageVersion` は `data/home.json` に保存され、画像とともに再起動後も残る。旧データの editors 未定義は空配列として読む。

- グループはだれでも作れて、一覧からだれでも入れる。メンバーはオンラインのフレンドを誘える
- イベントはタイトル・日時・グループ（任意）・会場のセッション（任意）を持ち、作った人は最初から参加者。だれでも参加表明できる
- 招待（セッション・グループ）はオンラインの相手にだけ届く通知で、ホームのベルと、セッション内の通知欄の両方に出る。「参加」「入る」でそのまま入る。フォローされた通知と招待はセッションに入っても消えない

## セッションのサムネイル

セッションカードの上部には最新のサムネイルを表示する。固定セッション（`sessions.json`）とユーザー作成セッションは同じ仕組みを使う。

サーバーは 3D の参加者から、参加者一覧で先頭の接続 ID を撮影役に選ぶ。撮影役が 2D に切り替えるか退出したら、残った 3D の参加者から同じ順序で選び直す。選出直後と、その後約 3 分ごとに `thumbnailRequest` を送り、撮影役の現在の 3D 視点を幅 320px・縦横比維持で撮影する。UI と自分の一人称パーツは写さず、シャッター音・フラッシュ・通知も出さない。3D でない場合や描画の準備ができていない場合は送信せず、次の依頼を待つ。

撮影には別のオフスクリーンレンダラーを使い、撮影後に破棄する。JPEG の品質は 0.65。サーバーは撮影役からの `thumbnailUpload` だけを受け付け、MIME が `image/jpeg`、デコード後のサイズが 64 KiB 以下であることを検証する。不正な送信は破棄し、画像の内容を含めずログに記録する。受理した画像はメモリ上の最新 1 枚を置き換え、`sessionInfo.thumbnail` として全員へ配信する。

画像がまだない場合と、3D の参加者がいない場合は、`WORLD_TINT` によるワールドごとの仮画像を表示する。画像領域は常に 16:9 で、更新によってカードの高さは変わらない。参加者が 0 人になったら撮影役と画像を破棄し、仮画像に戻す。画像は再起動後には残さない。

## 保存
作ったセッション・グループ（チャンネルも）・イベントは `data/home.json` に保存され（`sessions.json` のセッションを画面から改名したときの名前も `renamed` に入る。`sessions.json` は書き換えない）、再起動しても残る（`friends.json` と同じ）。開始から 30 日以上過ぎたイベントは、起動時とイベント作成時に取り除かれる。書き込みは変更が続いても 800 ミリ秒に 1 回へまとめられる（サーバー終了時は、保留中の分も書き出してから落とす）。セッション内のチャットは消えるが、アイテムは `data/items.json` から戻る。サーバーは `sessions.json` のセッションの後ろに `home.json` のセッションを並べ、人ごとに見えるものだけを `snapshot` と `sessions` メッセージで送る。

## アイテムの挿絵を更新する

原画は `client/assets/items/<id>.svg`、画面で使う PNG は `client/public/items/<id>.png`。標準 8 種の id は `note`・`hammer`・`chess`・`chessAi`・`g2048`・`canvas`・`camera`・`dice`。既存 UI の淡い背景色と輪郭線で統一し、SVG 内ではフォント・外部画像・外部リソースを使わない。2048 の数字もパスで描いている。

リポジトリのルートで次を実行する。

```sh
npm ci
npm run items:png
```

`scripts/rasterize-items.mjs` が sharp を使って、すべての原画を 360 × 240 px の PNG に変換する。sharp とその描画ライブラリはロックファイルで固定している。同じ SVG と依存バージョンで再実行すると同じ PNG を生成できる。原画を変えたときは PNG も生成し直し、両方をコミットする。`ITEM_INFO` の `illustration` が一覧と詳細の表示先を持つ。

3D の形状は `view3d/itemModels.tsx`・`cameraModel.tsx`・`diceModel.tsx` をセッションとプレビューで共用する。キャンバスのテクスチャ描画は `items/canvasDrawing.ts`。プレビューでは `createItem` の初期状態を渡し、同期・入力処理・セッションのストア購読は実行しない。マーケットの付箋商品の既存プレビューはそのまま使用する。

## セッションURLの共有

各セッションカードの「︙」から「セッションURLをコピー」を選ぶ。入室中は左上メニュー横の鎖ボタンでも参加中のURLをコピーできる。コピー結果は既存の通知で表示する。ボタンはTabキーで移動し、Enter/Spaceで操作できる。カードのメニューはEscapeで閉じる。

共有URLは `/#/session/<セッションID>`。開くと名前入力後に対象カードと参加ボタンを表示する。自動入室せず、既存のサーバー側参加確認を通す。URLを知っているだけでは招待やグループ参加資格は付与されない。存在しない・削除済み・閲覧できない対象はいずれも「このセッションには参加できません」と表示し、非公開情報を表示しない。現行の名前入力は本人確認を伴う認証ではなく、既存の名前ベースの権限判定を利用する。
