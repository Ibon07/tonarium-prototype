# パーティ戦闘貢献 v9（2026-10-31）

戦闘終了画面の「パーティ貢献」を開くと、各参加者の実効貢献を確認できる。通常表示は折りたたみ、韓国語・英語・日本語に対応する。旧保存データに詳細値がなければ表示しない。順位や異なる単位の合計点は作らない。

## 記録する値

- `damage`: 実際に失った敵HP。過剰ダメージは除外。直接攻撃、出血、発生元の分かる継続ダメージ・床・反射・奇跡を含む。
- `healing`: 実際に回復したHP。過剰回復は除外。再生、吸収、蘇生も含む。通常回復で瀕死の者は蘇生しない。
- `mana`: 実際に戻ったMP。自分への回復技能は消費MPを差し引いた純増。消耗品と奇跡も含む。
- `protection`: 明示的な防御、実際に使われた障壁、弱化・不屈・魔法抵抗支援によって失わずに済んだHP。攻撃時HPを上限とし、軽減→防御→障壁の順で差分を割り当てる。使われなかった障壁は0。複数術者の障壁は消費順に各術者へ残す。
- `control`: 実際の移動・詠唱の阻止、命中結果を変えた目くらまし・回避・魔法命中補助、状態異常の阻止・解除。単に状態を付与しただけでは増えない。同じ出所・対象・状態の妨害は1ラウンド1回。道がなく動けない相手の束縛も増やさない。
- `assistance`: 脆弱化・攻撃力支援による追加ダメージ。`damage` の内数に対応する別観点なので、両者を足して総ダメージにしない。
- `rescue`: 実際の蘇生・致死回避。運搬の持ち上げ直しは加点しない。

`allyHealing` / `allyProtection` / `allyRescue` は各値のうち、別のプレイヤーかその配下へ届いた分のみ。自己・自分の配下・自分の召喚は除外する。元の参加判定用 `effectiveActions` / `activeRounds` / `manualActions` は維持し、報酬配分・信仰・評判を戦闘コアから変更しない。

## 所有者集計・保存互換

`shared/fantasy-combat-contribution.ts` の純粋関数:

```ts
fantasyCombatContributionTotals(state, userId, generation)
```

プレイヤー本人と `ownerId`・`generation` が一致する配下の詳細値を一度ずつ合算する。個々の配下の値をプレイヤーの詳細値へ複写しない。召喚・部隊・組織の既存アクターを使用し、新しい戦闘効果を重ねない。発生元が倒れた後も、既に残した再生・出血などの実効分は元の発生者へ記録する。倒れたアクターが新しく行動できるようにはしない。

追加値は `contribution.receipts` の省略可能なフィールド。旧3項目だけの保存も有効。非整数・負数・未知キー、基礎量を超える `ally*` は拒否する。継続効果の `source`、アイテム条件の `contributor` も省略可能。アイテムによる状態の出所は学習技能の使用記録と分けるため、アイテム使用から技能経験を作らない。

## 聖職者の実効支援と神殿信仰

`server/fantasy-clergy-service.ts` の `recordFantasyClergyCombatService(profile, state, user)` は、勝利を確定するサーバー処理から、保存前のプロフィールへ呼ぶ。関数内では永続化しない。戦闘結果とプロフィールを同時に確定する責任は呼出側にある。

現在も聖職者で、戦闘時の職業も聖職者、同じ世代、離脱していない本人が対象。実プレイヤー2人以上の勝利で `allyHealing` / `allyProtection` / `allyRescue` の実効値がある場合だけ加算する。自己・自分の召喚への支援、単独、敗北、前世、転職後、未使用の技能は対象外。先に行った実効支援を、後の失神によって取り消さない。

1戦につき通常1点、他者へのHP回復と被害防止の合計50以上、または他者の蘇生・救命があれば2点。世界の1日4点、累計40点、保存する支援戦闘は最大30件。残り日次・累計枠が1点なら1点だけ加える。古い支援を削除して枠を再利用することはしない。少量支援のみを続けた場合は30件で30点となる。

`priestGrowth.support?: { battle: string; day: number; points: 1 | 2; hour: number }[]` に記録し、同時に `combatVictories['service:' + battle] = hour` を勝利証明として残す。時刻はプロフィールと戦闘の遅い方、日付は `floor(hour / 24)`。同じ戦闘は再処理・保存後の再読込でも二度加算しない。一般の勝利履歴300件整理では `service:` 証明を保全する必要がある。

成長データの検証は、時刻・日付・点数・重複・日次枠・累計枠・最大件数・証明時刻の完全一致を調べる。追加項目のない従来のv1記録も受け入れる。信仰に小さく加算するだけで、既存の奉仕依頼数、教理書、巡礼、誓約、祈り、熟練、聖者の条件や神殿ごとの信頼は変更しない。冒険者ギルドの功績はこの関数から与えず、金銭分配も行わない。

追加の22集中テストと型検査が成功（`clergy-service-focused.log`）。実際のパーティ回復→勝利、通常・大量支援、蘇生、他者防御、1戦重複、同日4点、累計40点、30件、単独・敗北・離脱・前世・別職・自己支援の除外、証明改ざん、旧v1互換を検証した。既存テストの奉仕依頼選択はカタログ順ではなく `fantasyPriestServiceQuest` で絞り、犯罪依頼の追加によって意図が変わらないようにした。
