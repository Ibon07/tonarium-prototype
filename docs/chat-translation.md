# チャットを表示言語へ自動翻訳する

Web版・Electron版のセッション内チャット、告知、DM、グループのチャンネル、セッションのまとめに含まれる会話ログが対象。訳文の下に原文を小さく表示し、元の発言言語を添える。言語が判定できなければ「不明」と表示する。表示言語を切り替えると、既存メッセージも新しい言語で表示する。顔の吹き出しと3Dの発言ラベルにも訳文を使う。

翻訳中・認証未設定・翻訳失敗・タイムアウトの間は原文を表示する。翻訳を待たずに送受信でき、入力中の本文も保持する。送信・保存・P2P配送には原文を使う。画像・動画・音声の内容や、ユーザー名は翻訳しない。ネイティブWindows版の独自UIは対象外。

開発者はまず次の設定を確認し、動作確認には「実APIを呼ばずに検証する」を使う。

## サーバーの環境変数を設定する

| 変数 | 設定方法と既定値 |
|---|---|
| `OPENAPI_KEY` | OpenAIの認証情報。サーバーの環境変数またはリポジトリ直下の未追跡の `.env` に設定する。未設定なら原文を表示する |
| `CHAT_TRANSLATION_PROVIDER` | `mock` または `openai`。`npm run dev` は既定で `mock`、通常起動は既定で `openai` |
| `CHAT_TRANSLATION_MODEL` | OpenAIのモデル名。既定は `gpt-4o-mini`。モックでは使わない |
| `CHAT_TRANSLATION_MOCK_FAILURE` | `mock` のとき `1` にすると翻訳失敗を再現する。通常は未設定または `0` |

本番ではデプロイ先のサーバー設定に `OPENAPI_KEY` と `CHAT_TRANSLATION_PROVIDER=openai` を登録してサーバーを再起動する。ローカルの実API利用も明示的に `openai` を指定する。認証情報は `VITE_` 接頭辞を付けず、クライアント設定、画面、ログ、Gitに含めない。変数名は依頼どおり `OPENAPI_KEY` とし、`OPENAI_API_KEY` は参照しない。

`openai` では本文と翻訳先言語がサーバーからOpenAIへ送られる。OpenAIとの通信はサーバーだけが行い、翻訳以外の会話履歴や環境変数をモデルへ渡さない。APIエラーの詳細はクライアントへ返さず、ログにも記録しない。モデル応答はテキストとして表示し、HTMLとして実行しない。

## 実APIを呼ばずに検証する

1. 認証情報は設定せず、サーバーの `CHAT_TRANSLATION_PROVIDER=mock` を指定して `npm run dev` を起動する。`--dev` 起動では未指定でもモックになる。
2. セッション内、DM、チャンネルで `Hello` を送る。日本語表示では `こんにちは`、韓国語表示では `안녕하세요` と小さな原文 `Hello`、発言言語「英語」が表示される。
3. 過去の発言を残してプロフィールの表示言語を変更する。訳文と発言言語のラベルが切り替わり、入力途中の本文が残ることを確認する。
4. `こんにちは`、`안녕하세요` を送り、元の言語がそれぞれ日本語・韓国語になることを確認する。`12345` は「不明」になる。
5. `CHAT_TRANSLATION_MOCK_FAILURE=1` でサーバーを再起動し、画面を再読み込みする。原文と翻訳失敗の案内が表示され、双方から次の発言を送受信できることを確認する。
6. 認証未設定の検証では `OPENAPI_KEY` を未設定にして `CHAT_TRANSLATION_PROVIDER=openai` で再起動し、画面を再読み込みする。原文と認証未設定の案内が表示され、送受信が続く。この状態ではOpenAIに接続しない。

モックは挨拶3言語と `ありがとう` / `Thank you` / `감사합니다` を辞書で変換する。他の本文は `[言語コード mock] 原文` と表示し、発言言語は「不明」にする。翻訳品質を検証する用途では使わない。

自動検証は `npm run test:translation`。翻訳結果、発言言語、不明判定、遅れて届く旧言語の応答、認証不足・失敗・タイムアウト時の原文表示、小さな原文のHTML、言語ラベル、実サーバーと2つのWebSocketクライアントによるDM送受信継続を確認する。OpenAIアダプターのHTTP通信はローカルのHTTPサーバーへ差し替え、成功・認証エラー・不正JSON・途中終了を検証する。実APIには接続しない。

## 翻訳処理を差し替える

`server/translation.ts` の `TranslationModel` は本文・翻訳先言語・中断シグナルを受け取り、`text` と `sourceLanguage` を返す。`createTranslator` に別のモデル関数を渡せる。モデルの拒否・不正応答・8秒のタイムアウトは共通の処理で原文へ戻す。同時実行はサーバー全体で8件までに制限し、超過時も原文を返す。

`POST /api/translate` の入力は `{ "text": "Hello", "targetLanguage": "ja" }`。本文は1〜2000文字（空白のみは不可）、翻訳先は `ja` / `en` / `ko`。成功時は `{ "text": "こんにちは", "sourceLanguage": "en", "status": "translated" }` を返す。判定不能は `sourceLanguage: null`、認証未設定は `status: "unavailable"`、失敗時は `status: "failed"` と原文を返す。不正入力は400、本文のバイト上限超過は413、POST以外は405。応答は `Cache-Control: no-store` とする。

画面側は本文と翻訳先の組み合わせごとにメモリで結果を再利用し、同じ発言の重複要求をまとめる。履歴が多い場合は順番待ちにし、画面からの同時要求を4件までに抑える。言語ごとに結果を分けるため、旧言語の応答が後から届いても現在の訳文を上書きしない。設定を変更した後は再読み込みで結果を取り直す。翻訳結果は永続化しない。

OpenAIへのリクエスト形式は[公式のStructured Outputsガイド](https://developers.openai.com/api/docs/guides/structured-outputs)に従う。ここでいうモックは、実APIを呼ばずに定型の翻訳結果を返す開発用のモデル関数を指す。設定や結果で疑問が残る場合は、秘密値を含めずにプロバイダー名・表示言語・再現手順を開発チームへ共有する。
