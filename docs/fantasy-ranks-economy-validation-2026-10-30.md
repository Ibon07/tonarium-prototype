작은 집과 대저택이 동시에 매물인 도시에서 종류만 반복 질문하던 실제 대화 문제를 수정했다. 해당 언어의 실제 매물 이름을 제시하고 이름으로 선택할 수 있으며, 선택 단계도 원래 인물·생애·개인 리비전·언어·유효 시간에 묶는다. 이미 팔린 작은 집을 요청해도 다른 대저택으로 흥정 대상을 바꾸지 않는다. 한국어/영어/일본어의 두 집 각각에 대해 별도 견적 후 확인 구매, 취소·경쟁 구매·오래된 상태·저장 실패를 검증했다. 부동산 대화 13건과 선택 파일을 포함한 `server-owned-final.log` 73/73이 근거다.

새 인물은 `jobHpVersion: 1`을 기록한다. 이 버전의 상한 초과 HP와 미지 버전은 저장을 고치지 않고 거절한다. 버전 없는 구형 인물만 같은 종족·성장·직업 추가 능력치·장비를 포함한 정확한 직업 보정 전 HP와 과거/현재 배율 중 큰 값의 상한 안에서 이전한다. 과거 마법사/궁수의 보정 전 상한, 격투가1.3·기사1.35·방패병1.45를 수용하되 그보다 큰 구형 HP도 거절한다. 이전은 현재 상한을 넘는 부분만 줄이며 HP를 회복하지 않는다.

기절·사망 인물의 입장 등급 계산을 건너뛰고, 진행 중 구형 전투의 기절 인물은 살아 있는 어댑터 재생성 대신 최대 HP/MP만 맞춘다. HP0·기절 기한·기술·소유권·시드·라운드·기존 동료 명령을 보존한다. `job-hp-migration-downed-red.log`는 기존의 `A living character is required` 재현이며 `job-hp-migration-final.log`는 신규 이전 5건·기절 전투·저장소 총48/48의 수정 후 결과다. 재시작이 반복돼도 HP 회복·변환 반복·파일 재저장이 없음을 확인했다. 선택적 신규 원장 파일이 없는 과거 소유자 이전 픽스처는 부재를 `null`로 기록하고 읽기 전용 미리보기·실패 복구 후에도 계속 부재임을 검사한다. 기존 원장은 바이트 동등 검사를 유지하며 `legacy-owner-final.log` 5/5다.

마지막 묶음 검증 `server-owned-final-with-hp.log`는 위 서버 범위와 파티·기절·배송·발견·경계·코호트·기본 저장소·직업 밸런스 검사를 포함해 **171/171 통과**다. 같은 시점의 `server-owned-final-typecheck.log`는 전역 타입 검사 종료 코드0이며 오류가 없다. 이 수치는 전체 프로젝트 테스트 수가 아니다.

후속 전체 검사에서 남은 의뢰·대화 5건도 확인했다. 일반 게시의 유효 시간은 현재 2시간이고 압력은 2시간마다2씩 회복하며50에서 멈춘다. 공동 토벌 테스트는 등록된 실제 공동 의뢰를 수락하고 현지 도착·출발 시각·공동 시작을 거친 뒤에만 참가자에게 진척이 공유됨을 확인한다. 대기 중 처치의 진척0, 중복 처치 영수증, 재시작 후 개인별 진척도 유지한다. 의뢰 수락 객체는 존재하지 않는 선택 필드를 `undefined` 값으로 만들지 않아 메모리와 JSON 재시작 결과가 정확히 같게 수정했다. 알 수 없는 객실 질문에는 실제 객실 대안을 안내하고, 질문 뒤의 단순 긍정만으로 예약·할인·결제·숙련 변경이 생기지 않음을 실제 웹소켓과 전체 프로필 동등성으로 확인했다. 최초 실패는 `server-triage-contracts-initial.log`, 수정 후 의뢰·통합·웹소켓·대화 행동·시장·부동산 이웃 검사 **64/64**는 `server-triage-contracts-final.log`에 있다. `server-triage-contracts-typecheck.log`는 전역 타입 검사 종료 코드0이다.
