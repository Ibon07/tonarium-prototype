# 3D 空間

## 二段ジャンプと左右リーン

Web / Electron の3D設定（左上の歯車）から個別に切り替える。端末の localStorage に `tonarium.doubleJump` と `tonarium.lean` を別々に保存し、再起動後も復元する。項目がない既存セーブでも二段ジャンプは無効、リーンは有効になる。

歩行モードで通常ジャンプした後、空中で Space を離して押し直すと一度だけ追加ジャンプできる。通常と同じ `JUMP_V`（4.2m/s）を上下速度に設定し、長押し・自動リピートでは発動しない。着地後は再使用可能。落下だけでは追加ジャンプできず、テレポート・移動モード変更・バイク乗車時には権利を解除する。追加ジャンプ中の高さは既存の位置同期で送る。

マウスロック中は Q で左、E で右に体と視点を最大10度傾ける（補間の時定数120ms）。一人称・三人称とも、角度に比例して視点をリーン方向へ最大25cmずらす。移動座標と当たり判定は動かさない。角度は既存の位置同期で約33ms間隔で送り、他参加者の体にも同じ角度を適用する。受信側では角度の二重補間をしない。両方押すと中立へ、離すと通常姿勢へ滑らかに戻る。道具保持・運搬・ドラッグ、照準先のバイク・乗車中、宵闇サバイバーズのプレイ中、入力欄への入力、ロック解除時はリーンを解除する。Q の手放しと E の乗降は既存処理を優先し、そのキーを離すまでリーンに転用しない。設定無効化・操作優先への移行では即座に傾きと視点の横ずれを解除する。角度が0になった状態は送信間隔を待たずに共有する。

確認手順：設定の初期値を確認し、片方ずつ切り替えて再読み込みする。二段ジャンプ有効時に Space の長押し、押し直し、3回目、着地後、足場からの落下で試す。複数クライアントで Q / E の左右・同時押し・解放を一人称と三人称で確認し、本人と他参加者の傾きの方向・角度が一致すること、視点だけが横へ動いて解除後に元へ戻ることを確認する。リーン中の設定無効化、道具の取得・設置・Qでの手放し、バイクへ照準を合わせて E で乗車・降車、入力欄へのフォーカス、Esc で双方から見て通常姿勢に戻り、既存操作が実行できることを確認する。自動テストは `npm run test:movement`、`npm run test:camera`、`npm run test:sync`。

## 歩行アニメーション

Web の3Dアバターは、歩行モード・接地中・非乗車で実際に水平移動しているときだけ、既存モデルの左右の足のアニメーションを再生する。衝突補正後の速度で判定し、開始は0.18m/s超、継続は0.08m/s超とする。停止・壁への押し当て・離地・フライ・ノークリップ・バイクや電車への乗車では停止する。歩行状態の変化は通常の位置送信間隔を待たず、既存の位置同期経路で送り、三人称の自分と他の参加者に反映する。

確認時は同じセッションに2人以上で参加し、三人称の自分と観察者の両方で、移動と停止、壁への押し当てと壁沿いの移動、ジャンプと落下・着地、フライ／ノークリップとの切り替え、バイクと電車の乗降を確認する。停止後に視点を動かさなくても足が止まること、乗車中は車両が動いても歩かないことも確認する。

## ワールド
- 設定（左上の歯車）の「ワールド変更」でワールド選択モーダルを開き、そのセッションの 3D 空間をホール／カフェ／ゲーム／宵闇サバイバーズ／街／ガーデン／AD 研究所に切り替えられる。誰でも切り替えられる。モーダルを閉じるか、選択後の確認でキャンセルすると変更されない
- 選ぶと確認が出る。「置いてあるアイテムをすべて片付ける」にチェックを付けると、切り替えと同時にアイテムが消える。確認すると全員の画面の上部に 3 秒のカウントダウンが出てから切り替わり、全員がスポーンエリアに戻される（ワールドごとに広さや家具が違うため）。3D の人には読み込みの画面が出る（長さはプロフィール設定の倍率に従う）。カウントダウン中はほかの切り替えを受け付けない
- カフェの家具（カウンター・テーブル・椅子・ソファ・植木）は通り抜けられず、アイテムが家具に重なったら外へずれる
- プロフィール設定の「軽量設定」をオンにすると、ワールドのポイントライト（カフェのペンダントライトやガーデンのランプの光）を読み込まない。ランプの見た目は残る。この端末にだけ保存される
- ワールドの種類と家具の当たり判定は `shared/worlds.ts`（当たり判定に高さの範囲 `y0`〜`y1` を付けると、その高さの間だけ効く）、見た目は `client/src/view3d/worlds3d.tsx`
- AD 研究所（`antimatter`）では、自分の反物質次元の進行を空間内の装置で確認・操作できる。詳しくは下の「AD 研究所」を参照

## AD 研究所

20m 四方の研究所。中央コア、8 基の次元リアクター、Sacrifice 祭壇、Big Crunch ポータルと、Infinity／Eternity／Reality／Celestials の展示がある。展示の購入機能はモック。進め方・セーブは [AD ポータルと研究所パネル](items.md#ad-ポータルと研究所パネル) を参照。

- 塔・コア・祭壇・ポータルに照準を合わせてクリックすると、対応する操作パネルが開いてマウスのロックが外れる。閉じたあとにキャンバスをクリックすると 3D 操作に戻る
- コア上の四面モニターに、反物質の所持量と毎秒の生産量が出る。画面は空間に固定され、カメラの方へ回転しない。各次元のボードには所持量・生産量・次の購入コストが出る。いずれも空間内の表示なので、撮影や配信にも写る
- 次元リアクターは、2D の次元カードと共通の色と環状の形を使う。所持量に応じて塔の高さが変わり、解放された装置の環や衛星が回転する。自分の研究所は距離によって装置や演出を簡略化しない
- コアの粒子は反物質の量に応じて密度・回転速度・広がりが増す。粒子数は 2,048〜24,576 個に抑える。次元の生産粒子はリアクターの周りを立体的に回り、高次元から一つ下の次元へ、第 1 次元からコアへ流れる。生産中の次元ごとに 128〜4,096 個で、未解放・生産停止中は出ない
- 購入成功時は対象の次元、Tickspeed や Boost・Galaxy・Sacrifice・Crunch の成功時はコアから粒子が広がる。1 回の次元購入は 2,400 個、コアでの操作は 3,600 個で、共通の粒子領域は最大 19,200 個。粒子は空間内にあり、手前の物に隠れる。OS の「視差効果を減らす」などの設定に従い、回転・生産粒子の動きを止め、購入時の粒子を省く
- 空は Poly Haven の CC0 写真素材「Qwantani Night (Pure Sky)」を同梱して表示する（[出典と加工内容](../client/public/sky/README.md)）。外周に見える壁はないが、歩行・フライ中の人とアイテムは従来の部屋と同じ範囲に制限される。装置の当たり判定も残る。ノークリップでは共通の移動設定どおり通り抜けられる
- 生産中はオリジナルの OGG 音楽が流れる。研究所パネルを開いている間は通常音量、3D 空間だけを見ている間はコアからの距離に応じた音量になる。操作音とともにドックの音量メニューの「サウンドボード・効果音」に従う。生産停止・非表示タブ・ワールド読込中・退出時は音楽を止める。再生には最初のクリックやキー入力が必要
- 配置と当たり判定は `shared/antimatterLayout.ts`、空間の構成は `client/src/view3d/antimatterLab.tsx`。数値計算と保存は共通の AD エンジン・ストアが担当し、3D はその表示と操作パネルへの入口を担う。状態は 250ms ごと、次元ボードは最大 1 秒ごとに更新する。空間内の表示に drei の Html は使わない

## ガーデンワールド

空の見える庭。芝生の床と 4m の壁は既存の部屋と同じ 20m 四方で、空・背景色・日光と庭のランプを組み合わせている。中央の散歩道から木陰のベンチや花壇を回れる。

- 木の幹・ベンチ・花壇・ランプの支柱は通り抜けられない。3D の人だけでなく、2D の人とアイテムにも共通の当たり判定を使う。散歩道は歩ける床の飾り
- スポーン位置は従来どおり中心 (0, 6.5)、半径 1.6。さらに人の半径 0.35m の余白を取り、家具が重ならないようにしている
- 配置と大きさは `shared/worlds.ts` の `GARDEN` にまとめ、見た目と当たり判定の両方で使う。庭の部品は `client/src/view3d/garden3d.tsx` のコンポーネントに分けてあり、木・ベンチ・花壇などを増やせる
- 床・壁・スポーン色と背景色、描画の切り替えは `client/src/view3d/worlds3d.tsx`。照準に当たる必要のない花・葉・散歩道などには `userData={{ noRay: true }}` を付ける
- 設定の「ワールド変更」とホームのワールド一覧から選べる。既存セッションの初期ワールドは変更しない。ランプのポイントライトはプロフィール設定の「軽量設定」で省略できる
- 部品はローポリのプリミティブと単色のマテリアルで構成し、外部モデルや画像テクスチャは追加していない。飾りを増やすときもポリゴン数とマテリアル数を抑える
- `npm run test:worlds` で登録・家具の当たり判定・スポーンと散歩道の安全性を確認できる

## 街ワールド

いろいろな場所での体験を試すための広い街（120m 四方）。配置・電車とエレベーターの動きは `shared/city.ts`、見た目は `client/src/view3d/city3d.tsx`、3D の足場と動く物の当たり判定は `client/src/view3d/cityPhysics.ts`。

- 真ん中が広場（スポーンエリア・噴水・木）。まわりに道路とビル（通り抜けられない）。地上の人と 2D の人は地上だけを歩く（2D はマップで歩く。マップには線路・駅・走っている電車が出る）
- **マンション**（北西「トナリウム・レジデンス」）：10 階建てと屋上。1 階は西の入口から入るロビー。2 階〜10 階は廊下と入れる部屋が 4 つ（机あり）。北東の角の階段（踊り場で折り返す）で歩いて上り下りでき、屋上まで出られる
- **エレベーター**：かごは 1 台をみんなで共有する（位置はサーバーの状態と時刻から全員同じに出る）。各階のドアの横の黄色いボタンで呼び、かごの中の壁のボタン（1〜10・R）で行き先を押す。押された階を順に回り、着くと 4 秒ドアを開けたまま待つ。かごが来ていない階のドアは閉まっていて通れない。ワールドを切り替えると 1 階に戻る
- **電車**：高架の環状線を時計回りに自動で走る 2 両編成。駅は北駅・東駅・南駅で、それぞれ地上から階段で上る。各駅で 10 秒止まり、その間ホーム側のドアが開いて歩いて乗り降りできる（ホームの線路側の柵は、電車が止まってドアが開いている間だけドアの位置が開く）。走っている間も車内を歩け、電車と一緒に動く。動きは時刻だけで決まるので、全員に同じ位置に見える。乗っている人は車内での位置も送り、見る側はそれを今の電車の位置に足して描く（走る電車の上でも遅れて車外に見えない）
- 高さのある場所では足元の高さも送る。声の届く距離・リストの距離・声の範囲チャットは高さの差も入れるので、マンションの別の階の人とは離れている扱いになる
- アイテムは地上に置かれる（上の階で出しても地上に置く）

## ゲームワールド（板わたり）
- ロビーはいつもの部屋で、北の壁がガラス。その向こうに 8×8 の板を 5 層に重ねた塔があり、ロビーから見える（天井は無い）
- ロビーの参加エリア（黄色の円）に 3D の人が 2 人以上入ったら、横のボタン（照準でクリック）で誰でも開始できる。そのとき参加エリアにいた人が参加者になり、最上段に飛ばされる
- 板は踏むと赤くなって震え、0.6 秒で消える。ジャンプで板を渡り、落ちないようにする。一番下の層より下に落ちると脱落してロビーのスポーンエリアに戻る。ゲーム中に 2D に戻る・抜けるのも脱落
- 最後まで残った人が優勝。ロビーの西の壁のメインモニターに、募集中は参加エリアにいる人、ゲーム中は参加者と生死、決着後は優勝者と順位が出る。8 秒後に板が元に戻り、次のゲームを受け付ける（勝者もロビーへ戻る）
- 進行はサーバー（`server/game.ts`）、板の配置や大きさは `shared/game.ts`、見た目は `client/src/view3d/game3d.tsx`。塔の上や落ちている間は足元の高さも同期する
- 2D の人は参加できない。メインモニターやついていくで観戦する

## 3D の操作（一人称・三人称）
- 操作ガイドと位置同期などの状態表示は、ドックの上の共通領域にガイド、状態表示の順で並ぶ。状態表示は件数と幅に応じて折り返し、ガイドとの間に通常 8px、低い画面では 6px の間隔を取る。ガイドの文章も折り返し、省略しない。領域は画面内の高さに制限し、長文などで収まらない場合は状態表示上でスクロールできる。ガイドと表示間の余白は背後の 3D キャンバスへの入力を通す。
- スマホ縦画面ではセーフエリアを含めてドックの上に配置する。横画面では右端のタブを避け、ガイドと状態表示を共通領域に保つ。2D の横画面の状態表示は従来どおり左下の独立した領域に表示する。
- 3D に入ると一人称で始まる。T を押すたびに一人称／三人称を1回切り替える。長押しのキーリピートや、チャット・付箋などの入力欄（contenteditable を含む）への入力中は切り替えない。マウスロック解除中も入力欄以外では切り替えられる。F5 は視点を切り替えず、ブラウザの通常の再読み込みを行う。
- 三人称では自分のアバターが表示され、頭付近を基準に視線と逆方向の真後ろへカメラを配置する。左右の肩越しオフセットはない。マウスで上下を向いても、水平面ではキャラクターの真後ろになる。
- 三人称の空間上（またはマウスロック中）でホイールを回すと、希望距離を 0.25m ずつ調整できる。初期値は 3m、下限 0.5m、上限 6m。一人称との切り替えでも希望距離は保持する。
- 頭付近から希望位置までレイを飛ばし、自分の体・照準用コライダー・一人称の手持ちモデルを除いた最も近い障害物から 0.15m 手前へ寄せる。電車の壁やガラスも対象。補正中は下限よりめり込み防止を優先して 0m まで近づけ、希望距離は変更しない。障害物がなくなると希望距離に戻る。定数とレイ判定は `client/src/view3d/playerCamera.ts`。
- 一人称に戻すと頭の位置からの従来の操作と手持ち表示に戻る。宵闇サバイバーズのプレイ中は、一人称側で既存の俯瞰表示を維持する。
- 設定メニューの「移動方法（自分のみ）」で「歩行」「フライ」「ノークリップ」を切り替える。初期値は歩行。現在のモードは画面下の操作案内で確認できる。
- 歩行は従来どおり WASD/矢印で移動、Space でジャンプ。フライとノークリップは重力なしで、WASD/矢印で前後左右、Space 長押しで上昇、左右どちらの Shift でも下降する。視点の上下とは独立して高さを操作する。
- フライは既存のコライダーと床・天井に衝突し、ノークリップは通り抜ける。切り替え時は上下速度と電車への追従を解除する。コライダー内部から歩行・フライに戻るときは、補正先の非貫通を確認し、近くに空きがなければスポーン周辺へ戻す。安全な位置が見つからない場合はノークリップを維持し、操作できる状態を保つ。
- 一人称視点の高さは自分のアバターの頭（目）の位置に合う。パラメータ・テクスチャ読み込み前は標準アバターの高さを使い、読み込み後に滑らかに追従する（時定数 200ms）。首・脚・頭の寸法を反映し、足元の高さやジャンプは別のオフセットとして加算する。
- 計算値・変更箇所・検証状況は [目の高さの検証記録](eye-height-verification.md) を参照。
- 画面をクリックするとマウスがロックされ、マウスで視点、WASD/矢印で移動、Space でジャンプ（ジャンプと顔の上下の向きはほかの人にも同期し、上部の顔表示にも出る。ジャンプは跳んだことだけを送り、見る側が受け取った瞬間から放物線を描くのでなめらか）。Esc でカーソルに戻る（ロック中は前面のパネルが薄くなって押せない）
- 他の人の位置・向きは約30Hzで受信し、表示は毎フレーム補間する。受信した座標は補間先として使い、Reactから表示位置を直接上書きしない。
- 操作はすべて画面中央の照準で行う: クリック = 操作、右クリック = 持ち運ぶ/置く、X = 片付ける、Q = 手に持った物を置く
- 付箋をクリックするとカーソルに戻って編集欄が出る
- 置かれている 2D の人は、他の人やアイテムと重なると少しずつ押し出される（スポーンエリアにいる間とついていっている間は除く）。2D の人がアイテムを出すときは、ほかの物や人と重ならない近くの場所に出る
- 入ってきた人は部屋の中の丸いスポーンエリアに現れる。3D には 2D でいた場所から入り、3D から 2D に戻ってもその場にとどまる（ドックの上の「スポーンに戻る」でスポーンエリアに戻れる）
- 2D で参加している人も同じアバターで、スポーンエリアか置かれた場所に立っている。ハンマーで叩けて、照準を合わせて右クリックで持ち運び、好きな場所に置ける（声もそこから聞こえる）
- チャットの発言は、上部の顔と同じく直近 30 秒、3D の人・2D の人の頭の上に吹き出しで出る（長い発言は途中まで）
- 自分のアバターは一人称では見えないが、カメラで撮ると写る（手に持って撮るときは除く）

## バイクの表示と操作

バイクはマーケットから購入する3D専用アイテム。所有アイテムから地上に出し、3m以内で照準を合わせて E またはクリックで乗車する。W/↑で加速、S/↓で制動、A/D・←/→で操舵、Eで降車する。乗車中はプレイヤーの位置と向きがバイクに追従し、画面に操作ヒントが出る。説明ウィンドウにも同じ操作を記載する。

乗車中はバイクの走行操作が優先され、降車後は設定した歩行・フライ・ノークリップの移動に戻る。乗車中の視点にもアバターの目の高さを反映する。マーケットと所有アイテムの共通詳細画面から、操作説明と車体の3Dプレビューを確認できる。挿絵がない場合は文字マークを表示する。

車体・前後輪・ハンドルは自前のプリミティブで構成する。車体の傾き、前輪とハンドルの舵角、速度から積算した車輪回転を表示する。見る側の位置・向き・傾きは受信したアイテム状態へ補間する。乗車者だけが固定ステップの走行計算を担当し、乗車の確定と他者の操作の拒否はサーバーが行う。

| 主な設定 | 値 |
| --- | --- |
| 計算の刻み | 1/120秒 |
| 最高速 / 加速度 / 制動力 | 10 m/s / 3.5 m/s² / 7 m/s² |
| 最大舵角 / グリップ上限 | 0.55 rad / 5 m/s² |
| 傾き係数 / 最大傾き | 1 / 0.65 rad |
| 車輪半径 / ホイールベース | 0.32 m / 1.3 m |
| 衝突半径 / 走行状態の送信 | 0.9 m / 20Hz |

地上の壁・障害物・境界は歩行と同じ衝突処理で停止する。後退・ジャンプ・二人乗り・上階や電車内の走行は対応しない。電車の自動運行・徒歩での乗降処理は従来どおり。全パラメータと同期・保存の詳細は [アイテムのバイク節](items.md#バイク) を参照。効果音の再生処理は効果音量に従う設計だが、[素材取得が未完了](assets.md)のため現在は無音。

## 3D アバター（お絵描きアバター）
- [oekaki-avatar](https://github.com/anthrotech-dev/oekaki-avatar) の形式。テンプレート（2048×1024）に描いた画像を 1 枚アップロードすると 3D アバターになる。oekaki-avatar で書き出した zip の `texture.png` と `manifest.json`（頭の大きさなどの調整値）も使える

- モデル・テンプレート・サンプルは oekaki-avatar から作者の許可を得て `client/public/oekaki/` に取り込んでいる

### 三人称カメラの検証

距離計算とキー入力の回帰テストは `npm run test:camera`。PR #132 の調査で、三人称の衝突用レイがスプライトにも判定を実行し、その後でメッシュ以外を除外していたことを確認した。名前ラベルなどの `Sprite.raycast` はカメラを必要とするが、衝突用レイには設定されておらず、フレーム処理が例外で止まる経路があった。判定前に可視メッシュへ絞り、自分の体・一人称モデル・透明なメッシュを除外するよう修正した。スプライトを含むシーンで20回切り替え、移動座標・視線更新とアイテム照準が継続する回帰テストを追加した。

実際の `THREE.Sprite` を含むシーンでも、修正前の `PlayerCamera.place` は `Raycaster.camera` 未設定による TypeError を発生させ、修正後は例外なく配置できることを Node 上で再現・確認した。

視点の切り替えでは同じ `PlayerCamera` と `Player` を維持し、移動キー・視線・持ち運び状態を初期化しない。ポインターロックの解除・再取得も行わない。入力欄の判定を視点切り替えより先に行い、F5 専用の `preventDefault` は削除した。

再確認の比較元は `0ae76eb0aa463874c9bdcd82c25bd372fce42332`。欠落していた既存履歴2件（言語選択のスタイル変更・設計文書の整理）を元の内容で復元し、未追跡だった言語選択の履歴も比較元との一致を確認した。今回分は `changelog/2026-10-25-camera-toggle-t.json` に記録している。ブラウザでの操作停止の実再現と、ロック中に移動・マウス視点・アイテム操作を続けながら反復切り替えする確認は未実施。
