# 単体ブラウザのWebXR初期対応

利用者向けの開始手順と、開発者向けの操作対応表・検証記録。最初は「VRを開始・終了する」「基本の割り当て」を読み、個別機能は対応表で確認する。

2026-10-27の座標変換修正、吹き出し・浮動UIの全生成経路、実施済み検証と残るQuest 3確認は[座標変換と回帰確認](webxr-coordinates.md)を参照。

Quest 3／Steam Frameの標準的な両手コントローラを対象にした初期実装。実機では未検証。外部iframeの映像、ブラウザのファイル選択などは、VRを終了して通常ブラウザで扱う経路を用意した。**全機能をVRセッション内だけで完結させる状態には達していない。** 不具合報告には端末・ブラウザ版・操作・VR終了後に復帰できるかを添え、READMEのフィードバック先へ連絡する。

## VRを開始・終了する

HTTPS（ローカル開発ではlocalhost）で開き、通常の画面からセッションに参加する。左メニューの「クライアントモード」にある「VR」で既存の3D画面を読み込んだ後、「VR開始」を押す。右上の「VR準備」は撤去した。端末にWebXRの `immersive-vr` と床基準の `local-floor` が必要。開始時の許可拒否・デバイス未接続・機能不足は画面へ表示し、通常画面を維持する。

ホームとセッション中のメニューでは、2D・3D・VRを等幅で一列に表示する。VRは準備時「VR」、開始可能時「VR開始」、起動中「VR終了」と表示する。利用条件はホバーまたはキーボードフォーカスで確認でき、Escapeで閉じる。無効な項目はラッパーへTabで移動して説明を読める。説明はスクロールするメニューの外に表示し、画面内に収める。ラベル・操作名・説明は日本語・英語・韓国語に対応し、対応確認後の言語変更にも追従する。

終了は仮想端末の「VR終了」またはヘッドセットのシステムメニューから行う。「2Dへ戻る」はVR終了後に既存の2D切替を実行する。従来の画面から2D切替・セッション退出を行った場合も終了させる。VR終了時は入力、ドラッグ、持ち運びを解除し、カメラの親・投影行列・視点モードと端末表示を復帰させる。位置は同じPlayerが保持する。フォーカス喪失・コントローラ切断でも入力を解除する。

開始前と非対応環境ではVR入力を登録しない。タッチ専用判定による通常3Dの制限は維持し、VR準備操作だけ既存の `setMode('3d')` を利用する。Electronはユーザーエージェントで判定し、補足に非対応を明示して開始を無効にする。補足ではElectron、HTTPS不足、WebXR API不足、対応確認中・失敗・非対応を参加前の案内より優先する。対応環境の説明にも実機未検証の注意を表示する。

## 基本の割り当て

| 入力 | 実行する操作 |
| --- | --- |
| 左スティック | 頭の向きに対して前後左右へ移動。バイクでは前後が加速・制動、左右が操舵 |
| 右スティック左右 | スナップ／スムース旋回。端末を指しているときはスクロール入力 |
| 右スティック上下 | レイ先のパネルをスクロール。地図などの独自wheel処理へも配送 |
| 左右トリガー | レイで端末のボタン・入力欄・Canvasを選択。押したまま移動で描画・ドラッグ。空間では既存の照準操作 |
| 左右グリップ | パネル上では押したまま移動・回転し、離して配置する。空間内ではレイ先を運ぶ／再押下で置く。保持した側のコントローラのレイから既存の床上配置を計算し、頭の向きには追従させない。2D参加者・配信ディスプレイも同じ処理へ渡す |
| A / X | ジャンプ、二段ジャンプ。フライ／ノークリップでは上昇。離すとキー解除 |
| B / Y | 通常パネルを一括表示／非表示。各パネルの配置は保持し、左腕の一覧と独立したVR操作面は残す |
| 端末「操作キー」 | Q/E/X/L/C/T/Tab/Escape、ジャンプ、下降、矢印キー、三人称距離、地図の中ボタンドラッグ、入力解除 |

設定画面の「VRの旋回」で、スナップ（初期30°、15〜90°）／スムース（初期90°/秒、15〜180°/秒）を選ぶ。端末の「操作キー」にも同じ設定がある。端末内でselectを選ぶと選択肢をボタンで表示する。値は `tonarium.xr.turn` に保存し、破損値・範囲外は補正する。スナップはスティックを中央へ戻すまで再発火しない。

## 文字と2D画面を仮想端末で扱う

左腕の一覧から各ウィンドウを個別に開閉する。複数同時に表示でき、グリップでそれぞれを移動・回転できる。プロフィールや確認などのダイアログも独立した面として登録される。VR終了・2D復帰・ブラウザ操作への切替・操作キー・文字入力・操作説明は、既存ウィンドウの外に表示する。表示は幅390px・高さ最大680pxを基準とした縦型で、DOM操作のボタン領域は最小44px。Canvasゲームは元の縦横比と座標を保つ。実機の可読性・選択性は未確認。

別セッションや別Reactツリーを作らず、各パネルの元DOMをThree.jsの `HTMLMesh` で約5fpsで描画する。Canvasゲームは元Canvasを描画し、入力は選択したパネルの元DOM座標へ戻す。SVGの描画も複製して表示する。レーザーと先端の丸印はパネルより後に描画し、深度テスト・深度書込を無効にして隠れないようにする。各クライアントが自分のパネルを生成し、他者のパネル配置・開閉は同期しない。既存の視点共有や空間カメラを使う場合、パネルがその映像へ映り込む可能性がある。

開始時の頭の追跡位置をアバターの目へ合わせ、以後の頭の平行移動と姿勢を反映する。左右の手はgripSpaceの位置・クォータニオンをモデルへ反映する。頭と手は既存avatarメッセージの任意の `xr` フィールドで送信し、サーバーと参加者の双方で検証する。追跡を失った手は次の送信で除去し、VR終了時は通常の姿勢へ戻す。チャット・ネームプレートは描画カメラのロールを相殺し、AD研究所・カメラ映像などのビルボードも世界座標の向きからロールを除く。

文字欄を選択すると端末内キーボードが開く。英数・かな・記号、空白・改行、末尾削除・全選択・確定を使える。漢字などは「Unicode」に16進コードを指定して「文字追加」（例: `7A7A` → 空、`1F600` → 😀）。IME変換は実装していない。日付・時刻・色は編集文字列を完成させて「値を適用」で反映する。既存フォームへの送信と入力イベントを使い、文字数制限を維持する。

端末はHTML/CSSの簡易描画で、通常画面と完全に同じ見た目を保証しない。アイコンだけのボタンはラベル文字で補う。外部iframe、外部画像、CSSの複雑な重なり、動画の更新、狭い画面の可読性には追加検証が必要。描画失敗時は通常ブラウザへ戻れる。

## 既存の表示・入力・同期と操作対応表

既存操作の入口は `App`、`Home`、`WorldScreen`、`WindowLayer`、`Player`、`items/panels`、各ゲームパネル。同期の送信口は `actions`・`items/actions`・`net/ws`・`net/session`、通話と映像はLiveKit。XR専用のメッセージ形式や権限は増やさず、同じ送信口へ入力する。

「端末選択」はレイ＋トリガーで通常のボタンを押す経路。「文字」は上記キーボード。「ブラウザ」は端末の「ファイル・外部画面をブラウザで操作」でVRを終了し、ヘッドセットのブラウザ用コントローラ操作に戻る経路で、VR内での完結ではない。

## 端末別の前提と残る検証

| 環境 | 今回の対応 | 未検証・制約 |
| --- | --- | --- |
| Quest 3 単体ブラウザ | 実行時のWebXR判定、床基準、`xr-standard` の軸・トリガー・グリップ・A/B/X/Y。DOM Overlayは要求しない | 実機の開始・終了、表示負荷、視認性、コントローラ割り当て、音声・ファイル選択。特定ブラウザ版の認証済み対応ではない |
| Steam Frame 単体ブラウザ | 同じ標準API・入力プロファイルを使う。機種名だけで開始可能と判定しない | ブラウザとランタイムが `immersive-vr` / `local-floor` を提供するかを含め未確認。PC接続を前提にしない |
| 通常のデスクトップ・スマホ | WebXRなし／拒否時は通常画面。VR準備前の動作は既存経路 | スマホの通常3D制限・画面共有制限は維持 |
| Electron | VR非対応と利用者に表示し、開始を無効化 | 2D・通常3Dを継続。ElectronのXRランタイム統合は対象外 |

仕様上の根拠は [WebXR Device API](https://www.w3.org/TR/webxr/) と [Three.js HTMLMesh](https://threejs.org/docs/#HTMLMesh)。DOM Overlayの機能有無へ依存しない設計にした。Quest 3／Steam Frameで動作を確認したという意味ではない。

## 初期実装時の検証履歴（今回の変更の検証結果ではない）

- `test:xr` と既存カメラ・移動・リーン・同期のテストを直接実行し、47件成功。軸の選択・デッドゾーン、スナップ再発火、旋回速度、設定値補正、Unicode・文字数制限、コントローラレイからの既存操作、既存参加者間の位置・イベント同期を確認した。
- `scripts/test-xr-browser.mjs` をChromeのヘッドレス環境で実行し、18項目成功。レイ相当の合成PointerEventで、Canvas座標、ドラッグ解除、range変更、Reactの制御入力への文字反映、select選択、端末開閉を確認した。Canvas画面の画素、開始・終了・許可拒否・表示中断時の入力解除、2Dモード変更時のセッション終了も確認した。セッションとrendererは模擬で、ステレオ描画・実際のXRフレーム・通常画面の全操作を含む切替の統合試験ではない。
- 型チェックと本番ビルドは成功。ビルドには従来と同種の大きなchunkの警告がある。
- `npm run check:completion` はVoltaのアクセス拒否で起動できなかった。代わりにNode 24.15.0の利用可能なランタイムで、履歴チェック（`--base HEAD`）、TypeScript、Viteを個別実行した。正式な完了チェックの成功とは扱わない。
- 実機検証、全機能の画面ごとのVR入力、VRから2Dへ切り替えた後の実ブラウザ入力、XR利用者を含む複数ブラウザでの音声・映像・同期、SVGの見た目、端末ごとのOSダイアログは未実施。これらを確認するまで受け入れ条件の全達成とはしない。

再実行は通常のNode/npm環境で `npm run test:xr`、`npm run test:camera`、`npm run test:movement`、`npm run test:sync`、`npm run check:completion`。ブラウザ模擬入力はPlaywrightを導入した環境で `node scripts/test-xr-browser.mjs`。既存Playwrightを使う場合は第1引数にモジュールのfile URL、第2引数にChrome実行ファイルを渡せる。テストは外部ネットワークを遮断し、ローカルの検証画面だけを操作する。

用語: レイはコントローラから伸ばす選択線、スナップは一定角度ずつの旋回、スムースは連続旋回、DOMは既存ブラウザ画面の要素、Canvasはゲーム等の描画面、Unicodeコードは文字を指定する番号。

今回の対象パネルと9条件の確認結果は [改修の対象と検証記録](webxr-acceptance.md) を参照する。実機未確認の項目は完了扱いにしない。

2026-10-28の変更では、パネル上部の「横幅を変更」「高さを変更」をトリガーで押したままドラッグして、本文のレイアウト寸法を変えられる。グリップで保持中はその手のスティック前後で距離を調整し、同じパネルを両手で保持すると比率を保って拡縮する。操作キー内のVR操作設定で、照準・選択中の移動制限を切り替えられる。初期値と旧設定からの復元時は制限が有効。

B/Yは左腕一覧と各パネルをまとめて隠し、再押下で個別状態と配置を戻す。閉じている間も終了・再表示の操作面は残る。端末の外装は [Blender制作元](../assets/xr/folding-phone/README.md) から生成する。寸法・入力の根拠は [座標とレイアウトの記録](webxr-coordinates.md) に記載した。
