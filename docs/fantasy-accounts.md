# 월드 전용 계정

판타지 RPG의 계정은 Tonarium 공통 화면의 표시 이름과 별개다. 공통 홈과 다른 월드는 기존 ID를 사용하며, 판타지 월드에서는 로그인한 계정의 캐릭터·소지품·직업·부동산·기록을 불러온다. 월드에서 나가면 공통 홈 ID로 돌아간다. 브라우저 저장소의 Tonarium ID를 월드 계정 ID로 덮어쓰지 않는다.

## 가입과 이어하기

판타지 월드에서 언어를 고른 뒤 **계정 만들기** 또는 **로그인**을 선택한다. 아이디는 영문·숫자·밑줄3~24자이며 대소문자를 구분하지 않고 소문자로 보관한다. 비밀번호는10~128자다. 캐릭터 이름은 이후 생성 화면에서 별도로 정한다.

가입하면 복구 코드를 한 번 보여 준다. 복사하거나 **파일로 보관**하고 안전하게 보관했다는 항목을 확인해야 여정으로 넘어간다. 복구 코드는 다시 조회할 수 없다. 비밀번호·복구 코드·로그인 티켓을 브라우저의 localStorage나 sessionStorage에 저장하지 않는다.

다른 기기에서는 같은 월드 아이디와 비밀번호로 로그인하면 같은 인물을 이어 간다. 한 계정은 한 로그인 세션을 사용한다. 새로 로그인하면 이전 세션의 인증이 무효가 되며 이전 기기는 다시 로그인해야 한다. 로그인 유지 기간은30일이고, 쿠키를 삭제했거나 기간이 끝났다면 다시 로그인한다.

계정 표시줄의 **계정**에서 비밀번호 변경·복구 코드 재발급·로그아웃을 할 수 있다. 비밀번호 변경과 코드 재발급에는 현재 비밀번호가 필요하다. 코드 재발급은 기존 코드를 무효화하며 새 코드를 한 번만 보여 준다. 새 로그인·비밀번호 변경·복구·코드 재발급 뒤에는 갱신된 세션으로 월드에 다시 연결한다.

## 비밀번호를 잊었을 때

월드 입구에서 **계정 복구**를 선택하고 아이디·보관한 복구 코드·새 비밀번호를 입력한다. 복구가 성공하면 이전 비밀번호와 복구 코드는 사용할 수 없고 새 복구 코드를 받는다. 새 코드를 다시 보관한다. 이메일이나 표시 이름만으로 계정을 복구하거나 다른 인물의 소유권을 넘겨 주지 않는다.

로그아웃·계정 변경·인증 상실 때는 이전 인물의 화면 상태와 대화 기록·처리 중 요청을 비우고, 서버에서 계정 소유자가 확정되기 전에는 개인 RPG 데이터를 표시하지 않는다. 공통 세계 시각은 유지한다. 캐릭터를 지우는 기능이 아니므로 다시 로그인하면 서버의 같은 인물을 불러온다.

## 이전 브라우저 저장의 캐릭터 연결

예전 브라우저 ID는 소유권을 증명하는 비밀이 아니므로, 알고 있다는 이유만으로 기존 캐릭터를 계정에 자동 연결하지 않는다. 운영자가 당사자를 확인하고 서버를 멈춘 상태에서 이전 저장을 예약된 월드 소유자로 옮긴 뒤, 한 번만 사용할 수 있는 연결 코드를 발급한다.

먼저 사용자는 새 월드 계정을 만들고 아직 캐릭터를 생성하지 않은 상태를 유지한다. 다음 명령은 예시이며 `<이전-소유자-ID>`는 저장 자료에서 확인한 실제 ID로 바꾼다. Node.js24 이상에서 프로젝트 루트를 기준으로 실행한다.

```powershell
node --experimental-transform-types scripts/fantasy-account-admin.ts --data-dir E:\tonarium2\data --principal <이전-소유자-ID>
```

기본 실행은 변경 계획만 보여 주고 파일을 쓰지 않는다. 실제 적용은 RPG 서버를 정상 종료하고 계획을 확인한 다음 실행한다.

```powershell
node --experimental-transform-types scripts/fantasy-account-admin.ts --data-dir E:\tonarium2\data --principal <이전-소유자-ID> --apply --server-stopped
```

적용은 먼저 기존 파일 묶음을 백업하고, 원래 브라우저 ID의 RPG 소유 참조를 새로운 `fantasy:UUID` 소유자로 함께 이전한다. 개인 진행과 관련 원장의 소유 참조를 따로 손으로 고치지 않는다. 완료되면 **24시간 유효한 1회 연결 코드**와 예약된 소유자 ID를 출력한다. 이미 예약 소유자로 옮긴 상태라면 그 예약 ID를 대상으로 코드를 다시 발급할 수 있다. 운영 중인 서버 잠금이나 미완료 복구가 있으면 적용을 거절한다.

코드는 확인한 당사자에게만 전달한다. 운영자가 RPG 서버를 다시 시작한 뒤, 사용자는 새 계정의 **계정 → 이전 캐릭터 연결**에서 코드를 입력한다. 이미 캐릭터가 있거나 다른 계정이 소유한 저장에는 연결하지 않으며 두 인물을 병합하지 않는다. 원래 브라우저 ID로는 이전한 RPG 소유자에게 접근할 수 없다. Tonarium의 다른 월드 진행은 이 이전 대상이 아니다.

## 저장과 운영

계정 자료는 `DATA_DIR/fantasy-accounts.json`에 저장한다. 비밀번호는 개별 salt를 사용하는 scrypt 해시, 복구 코드와 로그인 세션 값은 해시로 보관한다. 인증 자료와 [월드 백업](fantasy-backups.md)은 웹의 정적 파일 경로에 공개하지 않는다. 기존 계정 파일이 손상됐을 때 빈 계정 저장으로 자동 덮어쓰거나 같은 아이디를 새로 만들지 않고 운영 복구를 기다린다.

배포 환경의 계정 요청은 HTTPS를 사용한다. 로컬 테스트는 같은 기기의 `localhost`·`127.0.0.1`·`::1` HTTP 연결만 허용한다. HTTPS를 종료하는 역방향 프록시가 서버에 루프백 주소로 연결한다면 `FANTASY_TRUST_PROXY=1`을 사용한다. 기본값은 `0`이며 이 설정만으로 Docker 브리지나 임의 원격 주소를 신뢰하지 않는다.

Coolify·Docker의 역방향 프록시가 브리지 주소로 연결하면 **게임 서버에서 보이는 해당 프록시의 정확한 IP**를 `FANTASY_TRUSTED_PROXY_IPS`에 쉼표로 나누어 지정한다. 예를 들어 프록시의 고정 주소가 `172.18.0.2`일 때 `FANTASY_TRUSTED_PROXY_IPS=172.18.0.2`로 설정한다. 기본값은 빈 목록이다. 개별 IPv4·IPv6만 받으며 CIDR·와일드카드·호스트명·범위는 허용하지 않고 잘못된 항목은 신뢰하지 않는다. IPv4와 IPv4-mapped IPv6 표기는 같은 주소로 취급한다. 컨테이너를 다시 만들 때 주소가 달라지지 않도록 프록시에 고정 주소를 할당하거나 실제 주소를 확인해 설정을 갱신한다.

저장소의 `docker-compose.yml`은 위 두 설정을 `tonarium` 컨테이너에 전달한다. 운영자는 Coolify에 실제 프록시 IP를 입력하고 다시 배포해야 한다. 설정을 비운 채 PR만 반영하면 원격 HTTPS 계정 요청은 계속 거절된다. 데스크톱 앱도 같은 서버에 접속하므로 앱 재설치로 해결되지 않는다. 구체적인 확인 순서는 [배포 안내](deploy.md)를 따른다.

신뢰한 프록시는 외부에서 받은 `X-Forwarded-Proto`를 실제 연결 방식으로 덮어쓰고, `X-Forwarded-For`의 마지막 IP가 직접 접속한 클라이언트가 되도록 덮어쓰거나 추가해야 한다. 원래 `Host`를 유지해 브라우저의 `Origin`과 일치시킨다. 계정 HTTPS 판단과 접속 IP별 요청 제한은 같은 프록시 허용 목록을 사용한다. 허용하지 않은 주소가 보낸 전달 헤더는 두 판단 모두에 사용하지 않는다.

로그인은 HttpOnly·SameSite=Strict 쿠키를 사용하고 HTTPS에서는 Secure 쿠키를 쓴다. HTTP에서 받은 짧은 1회 티켓은 현재 WebSocket을 계정에 연결할 때만 사용하며, 티켓이나 월드 소유자 ID 자체를 장기 로그인 수단으로 저장하지 않는다. 변경 요청은 같은 출처와 요청 제한을 확인한다. 계정 기능의 경로는 `/api/fantasy/account/` 아래이며 공통 Tonarium 로그인 경로를 바꾸지 않는다.

서버 재시작·업데이트 전후 저장·계정·시계를 함께 다루는 백업과 복구 명령은 [월드 저장 백업과 복구](fantasy-backups.md)를 따른다. 여러 실제 PC의 장시간 접속·AI 성능과 최종 플레이 검수는 별도의 검증 작업이다.
