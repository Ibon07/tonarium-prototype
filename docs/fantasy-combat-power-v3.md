# 전투력 평가 v3 — 기술과 편성 동료

`shared/fantasy-adventurer.ts`의 전투력은 기존 능력치 기반 공격력×생존력의 제곱근에, 현재 전투 어댑터가 제공하는 기술과 동료의 제한된 기여를 반영한다. 승률을 직접 입력하거나 몬스터를 도전자에게 맞춰 바꾸지 않는다. 등급 경계 75/105/145/190/240/360/520은 유지한다.

## 상위 전투력 지수와 기존 기록

실제 어댑터의 기술 목록을 받는 평가는 개인 전투력 `p`를 계산한 다음, 440 이하는 그대로 두고 440 초과는 `440 + (p - 440) × 2.5`의 전투력 지수로 바꾼다. `fantasyCombatPowerIndex`가 이 순수 변환을 공개한다. 이 곡선의 꺾임점 440과 기울기 2.5는 모든 직업·종족에 같은 전역 값이다. 적·장비·종족·직업·시드별 승률표를 사용하지 않는다. 기술 목록을 받지 않는 능력치 전용/기존 문맥 호출과 합성 기준 표본은 기존 점수를 유지한다.

이것은 상위 등급 사이에 요구되는 실제 강함의 간격을 좁히는 변경이다. 등급 경계 숫자와 비교 기준 7등급 440/8등급 600은 유지하지만 마스터 진입 지수 520은 변환 전 개인 전투력 472에 해당한다. 이전의 520보다 실제 진입 요구가 낮아진다. 비교 기준 지수 600도 변환 전 개인 전투력 504에 해당하며 이전 600보다 낮다. 전투 능력치나 피해량을 직접 바꾸는 조정은 아니다.

기존 길드 등록 등급을 자동으로 내리거나 올리지 않는다. 저장된 심사 기록의 점수는 당시 평가의 역사적 값으로 남기고, 다음 심사부터 새 지수를 사용한다. 따라서 이전 심사 점수와 새 점수는 상위 구간에서 직접 비교할 수 없다. 승급은 지금처럼 현재 등급 의뢰 5개를 완료·보고한 뒤 한 등급씩 진행하며, 처음 등록은 1등급이다. 일반 조우 등급의 상한 6도 유지한다. 점수는 최종적으로 정수화하고 저장 형식의 상한인 10억을 넘지 않는다.

동료가 있으면 주인공과 동료의 개인 점수를 각각 지수로 바꾼 뒤 아래의 제한된 동료 기여를 더한다. 합계 전체에 다시 곡선을 적용하지 않는다. 따라서 개인 지수에 지원 전력을 더하는 의미이며 실제 어댑터가 전달하는 최대 2기 범위에서 동료 순서에 따라 결과가 바뀌지 않고, 동료 한 명당 주인공 지수의 35%·합계 70% 상한도 유지된다. 동료 자신의 동료를 재귀적으로 포함하지 않는다.

## 기술 평가

기술 문맥을 받지 않은 호출과 기존 `{ range, vocation }` 호출은 기존 점수를 유지한다. 어댑터의 기술 목록이 있으면 기본 공격을 포함한 12턴 계획을 비교한다. 한 가지 공격 기술과 한 가지 지원 기술의 사용 횟수를 선택하고, 나머지 턴은 기본 공격으로 채운다. 기술 개수나 서로 다른 기술서의 점수를 합하지 않는다. 같은 ID는 한 번만 읽고 동등하거나 열등한 선택지를 추가해도 점수가 늘지 않는다.

공격과 지원은 최대 MP를 함께 쓴다. 지원은 최대 6턴이며 해당 턴의 공격을 잃는다. 기본 계획보다 나쁜 계획은 선택하지 않는다. 따라서 약한 단독 방호가 있다는 이유만으로 전투력이 오르지 않는다. 주인공의 일시적 부상·MP 소모로 등급을 낮출 수 없도록 현재 HP/MP 대신 최대 HP/MP를 사용한다. 최대 MP보다 비싼 기술은 제외한다. MP 회복 기술, 소생형 기적, `miracle-*` 및 전장 전체 기적은 조건·재사용 대기·사망자 존재를 일반전에서 보장할 수 없어 제외한다. 일반 비전은 어댑터의 습득·무기 조건 검사를 통과한 경우에만 전달된다.

공격의 물리/마법 계수와 직업별 마법 공격 계수는 실제 전투에 맞춘다. 사거리를 명시한 기술은 `magic: true`일 때만 마법이며, 기존 사거리 생략 기술은 실제 전투처럼 마법 범위도 마법 판정에 포함한다. 명중 보정, 실제 사거리, 이동, 공격 형태, 추가 상태이상도 제한적으로 반영한다. 사거리가 짧은 마법 기술은 장거리 마법과 같은 사거리 보너스를 받지 않는다. 사거리·이동·범위·제어 보너스의 합은 공격 기여의 16%가 상한이다. 광역은 적이 여러 명일 가능성에 대한 작은 활용성 값이며 적 전체에 최대 피해를 준다고 가정하지 않는다.

회복은 실제 지능 계수와 기존 사제 회복 보너스를 사용한다. 일반 회복·방호는 실제 전투에서 자기 자신을 대상으로 사용할 수 있으며, `selfOnly` 회복과 사거리 0 자기 회복도 인정한다. 타인만 가능한 조건부 기적은 포함하지 않는다. 회복과 방호를 합한 추가 생존량은 최대 HP 두 번 분량으로 제한한다. 방호 한 번은 최대 HP의 1/3, 공격 기술에 붙은 방호는 한 번에 최대 HP의 1/12까지만 반영한다. 공격 부가 방호에는 지능 보너스를 더하지 않는다. 방호는 해당 라운드에만 유효한 능력이다.

재생·흡혈·약화·명중·축복 등은 실제 지속 시간과 상한을 참고한 제한된 생존/공격 값으로 평가한다. 지원의 추가 공격 기여는 전체 12턴 기본 공격량의 15%가 상한이다. 여러 지원 기술을 한꺼번에 쌓는다고 가정하지 않는다. 지형·적 유형에 따른 침묵·속박·광역의 효용은 정확한 승률 대신 작은 활용성 값이다.

## 1차 실측 이후 평가 예산 수정

`work/qa/balance-v3-2026-10-30/regular-screen0.json`에서 6등급 사제는 평균 12.25턴 동안 5.58회 회복했고, `apex-screen0.json`의 7등급 사제는 평균 13.59턴 동안 5.17회 회복했다. 6턴/지원 2회 제한은 이 자원 지속력을 다루지 못했다. 이에 12턴/지원 6회/추가 HP 2배 상한으로 수정했다. 공격과 회복이 같은 MP를 사용하고 회복 턴에는 공격하지 않는 조건은 유지한다. 이 예산은 장시간 무한 회복을 가정하지 않는다.

근접 표본의 접근 턴 손실이라는 설명은 이 실측과 맞지 않았다. 일반 전투의 전위는 x4, 적은 x5에서 시작하고, 실제 주력 근접 표본도 이동 없이 첫 턴부터 공격했다. 대신 후위 x1의 원거리 공격자는 적이 이동 2로 접근하는 동안 최대 2턴의 안전한 공격 기회를 얻는다. 기술 목록이 있는 실제 전투 문맥에는 이 구조를 초반 6턴의 피격 노출 4턴으로 근사하여 최대 1.5의 사거리/안전 계수를 사용한다. 실제 기술 사거리가 4 미만이면 선형으로 줄이며 근접 기본 계수는 1이다. 기술 문맥이 없는 기존 추정에는 원거리 1.08/마법 1.2를 유지한다.

안전 계수는 코드의 기본 위치와 보행에 근거한 휴리스틱이다. 모든 몬스터가 근접으로 이동한다는 보장, 모든 지형에서 2턴이 안전하다는 보장, 전 종족·직업·파티의 승률 예측이 아니다. 빠른 적·원거리 적·지형·전투 길이에 따라 달라지는 실제 효과는 별도 실측으로 확인해야 한다.

## 동료와 호출 지점

`server/fantasy-combat-adapter.ts`가 이미 편성됨·준비 상태·HP 양수·고용 가능 여부를 확인한 동료만 제공한다. 평가기는 최대 2명, 서로 다른 ID만 읽고 주인공 ID와 같은 항목을 제외한다. 동료는 자기 능력치와 기술로 계산한 전투력의 35%를 더하되 한 명당 주인공 개인 전투력의 35%를 넘지 못한다. 동료의 현재 HP/최대 HP 비율을 곱하여 부상과 이탈 가능성을 반영한다. 동료를 주인공 한 명과 동일한 전력으로 계산하지 않는다.

길드 심사, 저장된 일반 조우 등급, 몬스터 비교 도구는 모두 어댑터의 전체 플레이어를 평가 문맥으로 전달한다. 실제 편성 동료가 있는 비교 표본은 해당 편성 완료 뒤 점수와 등급을 계산해야 한다.

## 확인 범위

`shared/fantasy-combat-power-v3.test.ts`는 학습 기술의 기여, 중복/열등 기술 불변성, 공동 MP/턴 예산, 불가능한 기술 제외, 회복·방호의 행동 비용, 사거리/물리 마법 구분, 제한된 유틸리티, 동료 중복·생존·2명 상한, 기존 기준 점수와 소모 불변성을 검증한다. 상위 지수의 연속성·단조성·경계 대응·저장 상한·실제 평가와 기존 평가의 분기·동료 순서 불변성과 기여 상한도 검증한다. 실제 길드 심사·저장 후 재조회, 기존 직업/몬스터 기준, 회복 사거리, 마법진의 물리/마법 처리는 관련 기존 테스트로 확인한다.

이 점수는 설명 가능한 제한된 평가이며 전투 승률의 증거가 아니다. 등급별·직업별·일반종족별·파티별 전투 검증은 독립 시드 실측으로 별도 확인해야 한다. 실제 서버 장시간 플레이와 AI 대화 품질은 이후 운영 로그에서 확인한다.
