# Expeditions and Discoveries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 룬 중복, 연금술 발견, 지속 지형 효과, 성별에 따른 성인 명칭, 10위 랭킹, 무작위 던전과 불침번 야영을 기존 월드에 연결한다.

**Architecture:** 조합과 지형은 순수 공유 모듈에서 계산하고 서버가 재료·지식·좌표·성장을 검증한다. 던전은 저장한 시드로 재현하며, 랭킹과 야영 상태는 기존 원자적 저장에 포함한다.

**Tech Stack:** 기존 TypeScript, React, WebSocket, Node 24와 JSON 저장을 사용한다. 새 AI 모델이나 외부 의존성은 추가하지 않는다.

**Spec:** 이 대화의 사용자 요구와 후속 예외 규칙.

**최신 진행 지시:** 사용자가 요청할 때 테스트·검사를 일괄 실행한다. 개발 구현과 회귀 작성은 계속하지만 새 테스트·타입 검사·빌드·브라우저 검증·리뷰는 보류한다. [검사 대기 목록](../../fantasy-validation-backlog.md)에 미실행 항목을 모은다. 아래는 구현 상태이며, 완료 검사까지 통과했다는 표시가 아니다.

## Global Constraints

- 한국어·영어·일본어를 제공한다. 기존 작업·운영 저장·변경 이력을 보존한다.
- 같은 룬을 여러 칸에 넣을 수 있으나 칸 수·위력의 점감과 상한을 유지한다.
- 일반 합성은 사거리 또는 범위가 0 이하이면 금지한다. 자신에게 사용하는 축복·회복의 0은 예외이고 음수는 허용하지 않는다. 타인 대상 지원에는 실제 거리를 검사한다.
- 조합 결과는 성공적으로 제작하거나 해당 책을 읽었을 때만 공개한다. 실패와 취소는 성공한 제작·완료 의뢰로 집계하지 않는다.
- 랭킹은 서버 점수이며 최대 10개의 인생을 기록한다. 공개 필드는 닉네임·종족·직업·점수뿐이다. 사망 후 점수는 고정한다.
- 파티원은 자신의 동의 없이 야영·불침번 행동을 강제당하지 않는다.

## Review Focus

- 클라이언트가 결과 지식·점수·시드·불침번 인원을 조작해 이익을 얻을 수 없어야 한다.
- 저장 실패 시 재료·기록·랭킹·파티 상태가 부분적으로 확정되지 않아야 한다.
- 구형 조합과 던전 저장도 로드할 수 있어야 하며 재접속으로 추첨·특수방 보상을 반복하지 못해야 한다.
- 지속 타일의 진입·턴 시작 효과와 숙련도는 중복 집계하지 않는다.
- 동료·파티가 다른 장소나 다른 던전 방에 있으면 야영 지원을 공유하지 않는다.
